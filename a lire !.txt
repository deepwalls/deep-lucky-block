# LIVRE 0 — DÉMARRAGE RAPIDE

## §1. Les dix choses à savoir avant de toucher au code

**1. Tu ne peux pas compiler localement.** Il n'y a pas de JDK dans
l'environnement Arena, et tous les contournements de téléchargement échouent
(TLS). La seule voie est la CI GitHub. Procédure complète au §95.
**Ne perds pas de temps à réessayer `./gradlew build`.**

**2. Le temps journalisé par une passe n'est pas le temps écoulé.** Les passes
consomment 12 ms par tick de 50 ms. Un « 838 ms » dans le log vaut **3,5 s** de
temps réel. Détail au §20. C'est l'erreur de lecture la plus coûteuse de tout
le projet.

**3. Il y a déjà 20 balayages complets de la zone par structure.** Ajouter une
passe coûte 40 000 descentes de colonne et 1,3 Mo d'allocations.
🔒 **On n'ajoute pas de passe. On fusionne dans une descente existante.**

**4. `verifyGrassSurface` n'est pas seulement lente : elle est fausse.** Elle
peint du gazon sur tout sauf trois blocs codés en dur. C'est la cause du
« désert qui verdit ».

**5. Le bloc de surface ne se demande pas au biome.** En 1.21.1, il vient des
`SurfaceRules` du datapack. On l'obtient en **échantillonnant le terrain
naturel**, ce qui marche aussi avec les mods.

**6. `canSurvive` répond à la place d'une table sol↔plante.** Le cactus, la
canne à sucre et les plantes moddées connaissent leurs propres règles.

**7. Le hash de position remplace le générateur aléatoire.** Les passes sont
rejouées ; un RNG ferait scintiller les frontières.

**8. `getChunk` sur un chunk non chargé génère le chunk en pleine boucle.** Une
seule colonne mal placée coûte 15 secondes. Reste dans la zone épinglée par
`ChunkKeeper`.

**9. Les sources de production ne sont pas toutes suivies par Git.**
🔒 `git reset --hard`, `git checkout` destructif et `git clean` sont
**interdits**.

**10. `fixLiquids` (34,3 s) et `preload` (30,6 s) font 61 % du temps du
dragon.** L'habillage de surface, même parfait, ne fera pas passer le dragon
sous 30 s. Ne confonds pas les deux chantiers.

## §2. Les six invariants

🔒 **I1.** La palette de surface s'échantillonne **avant toute édition** du
terrain. Après le lissage, on ne lit que de la pierre reconstruite.

🔒 **I2.** Le drainage des bassins passe **avant** l'habillage. Sinon on pose
une dalle d'herbe au-dessus d'une poche d'eau.

🔒 **I3.** Le tramage est **déterministe** : hash de position, jamais
`level.getRandom()`.

🔒 **I4.** On compare des **`Block`**, jamais des `BlockState`. Sinon
`snowy=true` déclenche un mélange invisible entre variantes du même bloc.

🔒 **I5.** On **n'ajoute jamais une passe** de balayage. On fusionne.

🔒 **I6.** Toute lecture de bloc reste **dans la zone épinglée** par
`ChunkKeeper`.

## §4. Glossaire

| Terme | Définition |
|---|---|
| **Colonne** | un couple `(x, z)`. Toutes les passes de terrain raisonnent en colonnes. |
| **`surfY`** | Y du **premier bloc solide** en descendant. Varie par colonne. |
| **Passe** | un balayage complet de la zone, découpé en tranches d'un tick. |
| **Tranche (slice)** | le travail d'un tick : au plus `BATCH_COLS` colonnes **et** `SLICE_BUDGET_MS` ms. |
| **Anneau (`ring`)** | marge ajoutée autour de la structure. `terrainRing()`. |
| **Emprise (footprint)** | le rectangle de la structure. Protégé par `protectFootprint`. |
| **Palette** | le couple (bloc de surface, bloc de sous-sol) dominant d'un chunk. |
| **Tramage (dithering)** | choisir un bloc ou l'autre par tirage, pour simuler un dégradé. |
| **Chemin rapide** | le cas « aucun voisin différent » : on écrit sans calculer. |
| **Chunk-majeur** | ordre de parcours qui épuise un chunk avant de passer au suivant. |
| **Enveloppe** | le contour de la bande de transition, par opposition à son contenu. |
| **Domain warping** | perturber une distance par un bruit, pour casser les lignes droites. |
| **Temps CPU cumulé** | ce que journalisent les passes. À diviser par 0,24 pour le temps réel. |
| **`FAST_FLAG`** | `2 \| 16 \| 32` : pose sans mise à jour de voisinage. |
| **MSPT** | millisecondes par tick. Au-delà de 50, le serveur prend du retard. |
| **`[DLB-PERF]`** | préfixe de log des mesures de temps par poste. |
| **`[server-check]`** | marqueur de commit qui déclenche le test serveur en CI. |
| **Palette confiante** | palette issue d'au moins 8 témoins exploitables sur 16. |
| **Sel (salt)** | entier qui décorrèle deux usages du même hash. |

## §8. Les deux méthodes fautives, en clair

### §8.1 `verifyGrassColumn`, ligne 3915

```java
private static void verifyGrassColumn(ServerLevel level, int x, int z, int[] counters) {
    if (isProtected(x, z) || StructureScatterDecor.isInsideDecor(x, z, 1)) return;
    BlockPos.MutableBlockPos mut = new BlockPos.MutableBlockPos();      // (A)
    int surfY = deepluckyblock.util.SafeSurface.height(
            level, Heightmap.Types.MOTION_BLOCKING_NO_LEAVES, x, z) - 1;
    if (surfY < 1) return;
    BlockState s = level.getBlockState(mut.set(x, surfY, z));           // (B)
    if (s.isAir() || isLog(s) || isLeaf(s)) return;
    boolean snowy = isSnowy(level, mut);                                 // (C)
    if (s.is(Blocks.SNOW_BLOCK) || s.is(Blocks.PACKED_ICE) || s.is(Blocks.BLUE_ICE)) {
        if (level.getBlockState(mut.set(x, surfY + 1, z)).isAir()) {
            level.setBlock(mut, Blocks.SNOW.defaultBlockState(), 3);     // (D)
            counters[1]++;
        }
    } else if (snowy) {
        if (s.blocksMotion() && isNaturalTerrain(s) && !s.is(Blocks.GRASS_BLOCK)
                && !s.is(Blocks.SAND) && !s.is(Blocks.SANDSTONE) && !s.is(Blocks.RED_SAND)) {
            level.setBlock(mut.set(x, surfY, z), Blocks.GRASS_BLOCK.defaultBlockState(), 2);
            counters[0]++;
        }
        if (level.getBlockState(mut.set(x, surfY + 1, z)).isAir()) {
            level.setBlock(mut, Blocks.SNOW.defaultBlockState(), 3);
            counters[1]++;
        }
    } else if (s.blocksMotion() && isNaturalTerrain(s) && !s.is(Blocks.GRASS_BLOCK)
            && !s.is(Blocks.SAND) && !s.is(Blocks.SANDSTONE) && !s.is(Blocks.RED_SAND)) {
        level.setBlock(mut.set(x, surfY, z), Blocks.GRASS_BLOCK.defaultBlockState(), 2);  // (E)
        counters[0]++;
    }
}
```

**Cinq défauts, repérés (A) à (E) :**

**(A)** une allocation de `MutableBlockPos` **par colonne** — 40 176 objets
jetables par passe.

**(B)** `level.getBlockState` refait la résolution chunk → section → palette à
chaque appel, alors que `readBlock` existe (T71).

**(C)** `isSnowy` compare des **chaînes de caractères** sur le nom du biome,
**par colonne**, alors que le biome est stocké par cellule de 4×4×4. C'est au
minimum 16 fois trop souvent, avec le pire outil possible.

**(D)** flag `3` : mise à jour de voisinage, cascades possibles.

**(E)** ⚠ **le bug fonctionnel** : le sable est exclu par une liste en dur de
trois blocs. Terracotta, gravier, mycélium, podzol, neige, et **tous les sols
moddés** sont convertis en gazon. C'est la cause directe du « désert qui
verdit ».

### §8.2 `naturalizeColumn`, ligne 4399

Sa première instruction utile est :

```java
if (surface.is(Blocks.GRASS_BLOCK)) {
    // ... tout le reste de la méthode
}
```

⚠ **Aucune végétation n'est posée si la surface n'est pas du gazon.** Après un
lissage qui reconstruit en pierre, `naturalize` saute donc toute la zone
remodelée. C'est exactement le symptôme rapporté en jeu : « pas de plantes sauf

Les deux bugs se renforcent : `verifyGrassSurface` met du gazon partout pour que
`naturalize` fonctionne, et c'est ce gazon qui verdit le désert.
🔒 **Les deux méthodes doivent être corrigées ensemble, ou pas du tout.**

# LIVRE II — LA THÉORIE DONT TU AS BESOIN

Ce livre explique les mécaniques de Minecraft 1.21.1 qui gouvernent tout le
reste. Si tu connais déjà ces points, saute au Livre III.

## §11. Comment le monde est stocké

### §11.1 Chunk, section, palette

Un **chunk** fait 16 × 16 blocs horizontalement et toute la hauteur du monde.
Il est découpé verticalement en **sections** de 16 × 16 × 16 = 4 096 blocs.

Chaque section contient un `PalettedContainer<BlockState>` : au lieu de stocker
4 096 états complets, elle stocke une **palette** des états distincts présents
plus un tableau d'indices compacté. Une section de pierre pure ne stocke donc
qu'**un seul** état.

Conséquences pratiques, et elles sont énormes :

```java
// Énumérer les états DISTINCTS d'une section, sans parcourir 4096 blocs :
section.getStates().getAll(state -> { /* ... */ });
```

Si une section ne contient qu'un seul état, elle est **uniforme par
construction** : inutile de la scanner. Si elle ne contient aucun bloc de sol
candidat, le chunk peut être écarté immédiatement pour le calcul de palette.

### §11.2 Le coût d'une lecture de bloc

```java
level.getBlockState(pos)
```

fait, à chaque appel :

1. calcul de `pos.getX() >> 4`, `pos.getZ() >> 4` ;
2. recherche du chunk dans la carte de chunks du `ChunkSource` ;
3. calcul de l'index de section `getSectionIndex(y)` ;
4. accès au `PalettedContainer` ;
5. décompactage de l'indice et résolution dans la palette.

Les étapes 1 à 3 sont **constantes pour toute une colonne**, et les étapes 1-2
sont constantes pour **tout un chunk**. Les refaire par bloc, c'est 90 % de
travail inutile.

La version rapide, **déjà écrite dans le mod** (bloc `T71`) :

```java
LevelChunk chunk = level.getChunk(cx, cz);                  // UNE fois par chunk
LevelChunkSection[] sections = chunk.getSections();
int idx = chunk.getSectionIndex(y);
LevelChunkSection sec = sections[idx];
BlockState st = sec.getBlockState(x & 15, y & 15, z & 15);  // coordonnées LOCALES 0..15
```

⚠ `LevelChunkSection.getBlockState` prend des coordonnées **locales 0..15**.
Lui passer des coordonnées absolues ne lève pas d'exception : il lit un autre
bloc. C'est un bug silencieux.

**Comptage actuel dans le fichier : 5 appels à `readBlock` contre 63 à
`level.getBlockState`.** L'outil existe et n'est pas utilisé.

### §11.3 ⚠ Le danger de `getChunk`

Un `getChunk` sur un chunk **non chargé** déclenche sa **génération
synchrone**, dans le tick courant. Mesure documentée dans le commentaire T53 de
`SafeSurface` : **une seule colonne** tombant dans un chunk absent a coûté
**~15 secondes** sur un monde neuf. C'est aussi l'origine du gel de 27 s au
préchargement.

🔒 Toutes les lectures doivent rester dans la zone épinglée par `ChunkKeeper`.
Le mod fournit `SafeSurface.isLoadedAt(level, x, z)` : utilise-le avant tout
accès hors de la zone certaine.

## §12. Les biomes en 1.21.1

### §12.1 Stockage par cellule de 4×4×4

Depuis 1.18, le biome n'est plus stocké par colonne mais par **cellule de
4×4×4 blocs**, et les frontières sont **brouillées (fuzzed)** par le
générateur pour éviter les lignes droites.

Deux conséquences :

1. **Un chunk n'est pas une unité de biome.** Un chunk 16×16 contient 16
   cellules de biome horizontalement, potentiellement différentes.
2. **Lire le biome par colonne est 16 fois trop souvent.** Le résultat est
   constant sur chaque cellule 4×4.

### §12.2 ⚠ Il n'existe pas d'API `biome → bloc de surface`

C'est le point qui oriente toute la conception. En 1.21.1, le bloc de surface
d'un biome est produit par les **`SurfaceRules`** définies dans le datapack du
générateur de monde. Il n'y a **aucune méthode** du type
`biome.getTopBlock()`.

Et même s'il y en avait une, elle serait fausse pour les mods : un mod de
biomes peut poser ce qu'il veut par ses propres règles.

🔒 **On n'interroge pas le biome. On échantillonne le terrain réel.** C'est la
décision D1 (§92), et elle rend le système automatiquement compatible avec tous
les mods de biomes, sans configuration.

Le biome ne sert que pour deux choses accessoires : le test « enneigé »
(texture de l'herbe) et, en option, la liste des features de végétation (§45).

## §13. Les heightmaps

Une heightmap est un tableau 16×16 par chunk, entretenu par le jeu, qui donne
pour chaque colonne la hauteur du premier bloc satisfaisant un critère.

| Type | Critère |
|---|---|
| `WORLD_SURFACE` | premier bloc non-air |
| `MOTION_BLOCKING` | premier bloc qui bloque le mouvement **ou** contient un fluide |
| `MOTION_BLOCKING_NO_LEAVES` | idem, **sans compter les feuilles** |
| `OCEAN_FLOOR` | premier bloc solide, en ignorant les fluides |

⚠ **`MOTION_BLOCKING_NO_LEAVES` ne donne pas le sol.** Elle compte les
**bûches**. Chez l'épicéa, dont le tronc dépasse la cime, elle renvoie le haut
du tronc. Le commentaire T76 de `scanTrees` documente une mesure : un saut basé
sur la comparaison des heightmaps avait fait passer le comptage de **19 arbres
à 11**.

🔒 **Utilise la heightmap comme borne haute, puis descends bloc par bloc.**
C'est ce que fait `groundSurfaceY` (ligne 3729).

## §14. Les drapeaux de `setBlock`

`level.setBlock(pos, state, flags)` — les bits utiles :

| Bit | Valeur | Effet |
|---|---|---|
| 1 | 1 | prévenir les voisins (mise à jour de blocs) |
| 2 | 2 | envoyer aux clients |
| 4 | 4 | ne pas re-rendre |
| 8 | 8 | re-rendre sur le thread principal |
| 16 | 16 | **ne pas** propager la mise à jour aux voisins |
| 32 | 32 | **ne pas** faire tomber les blocs affectés par la gravité |

Le mod définit :

```java
private static final int FAST_FLAG = 2 | 16 | 32;   // ligne 83
```

soit : *envoyer au client, sans mise à jour de voisinage, sans gravité*.

⚠ **Le flag `3` (= 1 | 2) est dangereux ici.** Il déclenche les mises à jour en
chaîne : du sable qui tombe, de l'eau qui coule, des plantes qui se cassent.
`verifyGrassColumn` l'utilise pour la neige (lignes 3927 et 3936) : à corriger.

Cas particulier utile, détaillé au §64 : le bit 16 est **ce qui permet de poser
une plante double sans qu'elle se casse**.

## §15. Le système de tranches du mod

C'est la mécanique la plus importante à comprendre pour tout ce qui touche à la
performance.

Une passe ne s'exécute pas d'un bloc. Elle est découpée par `ColumnPass`
(ligne 2087) :

```java
private static final int  BATCH_COLS      = 192;   // ligne 2030
private static final long SLICE_BUDGET_MS = 12;    // ligne 2038
```

À chaque tick, `slice()` traite des colonnes jusqu'à épuiser **soit** 192
colonnes, **soit** 12 ms, puis se replanifie au tick suivant.

Le budget est adaptatif (`sliceBudgetMs`, ligne 2053) :

| MSPT | facteur | budget |
|---|---|---|
| ≥ 65 | 0,25 | 3 ms |
| ≥ 55 | 0,5 | 6 ms |
| ≥ 45 | 0,75 | 9 ms |
| 25-45 | 1,0 | 12 ms |
| ≤ 25 | 1,75 | 21 ms |

borné à `[2, 24]` ms.

`ColumnPass` gère aussi, et c'est important à ne pas casser :

- `ChunkKeeper.keep(level)` et `TerrainChain.heartbeat()` **à chaque tranche** ;
- le **report** de tranche si la zone n'est pas entièrement chargée
  (`zoneReady()`, jusqu'à 1 200 reports) ;
- les colonnes **manquées** (chunk absent) stockées dans `missed`, rejouées
  jusqu'à `MAX_MISS_RETRIES = 60` ;
- la détection de **colonnes lentes** (`SLOW_COLUMN_MS = 50`) ;
- un **garde anti-doublon** : une seule passe d'un même label à la fois.

🔒 Toute nouvelle passe doit réutiliser `ColumnPass`, ou reproduire ces cinq
comportements. Une passe qui oublie `keep`/`heartbeat` voit sa zone relâchée en
plein travail, et toutes les colonnes suivantes tombent sur des chunks absents.

## §16. `canSurvive` : la règle du jeu, pas la nôtre

```java
BlockBehaviour.BlockStateBase.canSurvive(LevelReader level, BlockPos pos)
```

Chaque bloc de plante implémente cette méthode et y encode **ses propres
règles**. Exemples :

- `SugarCaneBlock.canSurvive` teste le sol valide **et** la présence d'eau sur
  l'un des 4 côtés du bloc support ;
- `CactusBlock.canSurvive` teste le sable **et** l'absence de bloc solide sur
  les 4 côtés ;
- `BushBlock.canSurvive` teste `mayPlaceOn` ;
- **les plantes moddées implémentent la même méthode.**

🔒 **On n'écrit pas de table sol↔plante. On appelle `canSurvive`.**

Complément côté sol, spécifique à NeoForge :

```java
IBlockExtension.canSustainPlant(state, level, pos, Direction, IPlantable)
```

utile si un sol moddé accepte des plantes que `canSurvive` refuserait.
⚠ Note : NeoForge a **supprimé** l'ancien système `PlantType` en 21.0 et l'a
remplacé par `SpecialPlantable` + `canSustainPlant`. Les extraits de code
antérieurs à 1.21 ne compilent pas.

### ⚠ Piège connu : `canSurvive` et la lumière

Bug réel documenté en 1.21.1 : des plantes dont le `canSurvive` teste la
luminosité **échouent silencieusement pendant la worldgen**, parce que
`getRawBrightness` renvoie 0 avant que le moteur de lumière ait tourné.

Nous posons **après** la génération, donc hors de ce cas. Mais **c'est la
première piste à explorer si des plantes disparaissent sans aucune erreur dans
le log**.

## §17. ⚠ Le piège des noms de tags entre versions

En **1.21.5**, le tag `dead_bush_may_place_on` a été **renommé**
`dry_vegetation_may_place_on`.

En **1.21.1**, c'est l'**ancien nom** qui est correct.

Copier un extrait de code récent trouvé en ligne **casse la compilation**, avec
une erreur qui ne dit pas « mauvaise version ». C'est le contrôle statique n°1
du §88.

🔒 **Règle générale : toute recherche web doit inclure la version.** Par
exemple `site:docs.neoforged.net 1.21.1 chunk ticket`. Une réponse sans version
est une réponse inutilisable.

## §18. Déterminisme : pourquoi pas `level.getRandom()`

Les passes de ce mod **sont rejouées**. `ColumnPass` garde les colonnes dont le
chunk était absent (`missed`, ligne 2119) et les retraite jusqu'à 60 fois. Une
même colonne peut donc être évaluée à plusieurs ticks d'intervalle.

Avec `level.getRandom()`, la même colonne obtiendrait un tirage différent à
chaque évaluation : la frontière **scintillerait**, et le résultat dépendrait de
l'ordre de chargement des chunks — c'est-à-dire de rien de reproductible.

🔒 **Le tirage doit dépendre uniquement de la position.** C'est la décision D3
(§92).

Le mod contient déjà `hashNoise` et `valueNoise2D` (lignes 3491 et 3499) : lis
ces deux méthodes avant d'en écrire de nouvelles, il y a peut-être de quoi
réutiliser.

# LIVRE III — LE BUDGET DE TEMPS

## §19. La contrainte

**L'étape d'habillage de surface doit tenir en 1 seconde de temps écoulé.**

Exigence explicite de l'utilisateur. 🔒 **Ne jamais relâcher ce seuil pour
faire passer un test.**

## §20. ⚠ L'erreur de lecture qui fausse tout

`verifyGrassSurface` est journalisée à **838 ms pour 40 176 colonnes**.

**Ce chiffre est du temps CPU cumulé, pas du temps écoulé.**

Une tranche consomme au plus **12 ms par tick de 50 ms** : le rapport cyclique
est de **24 %**.

> **838 ms de CPU ÷ 12 ms par tick = 70 tranches = 70 ticks = ~3,5 s de temps
> écoulé.**

Une passe qui ne fait presque rien dépasse donc déjà le budget d'un facteur
**3,5**.

🔒 **Règle de lecture des logs de ce mod :** tout temps journalisé par une passe
découpée doit être **multiplié par ~4,2** (50/12) pour obtenir le temps
réellement écoulé. Seul le `[DLB-PERF]` global est du temps écoulé.

## §21. Le budget chiffré

| Grandeur | Valeur |
|---|---|
| Temps écoulé autorisé | 1 000 ms |
| Ticks disponibles | 20 |
| CPU disponible (20 × 12 ms) | **240 ms** |
| Colonnes (mesure dragon du 27/09) | 40 176 |
| **Coût maximal par colonne** | **≈ 6 µs** |

Référence actuelle : `verifyGrassSurface` = **20,9 µs/colonne**.

Il faut **diviser le coût par colonne par 3,5 tout en faisant davantage de
travail** (surface + sous-sol + tramage + perturbation + végétation + repose des
plantes sauvées).

## §22. La démonstration d'impossibilité

| Scénario | µs/col | CPU | Temps écoulé |
|---|---|---|---|
| `verifyGrassSurface` seule, aujourd'hui | 20,9 | 838 ms | ~3,5 s |
| `verify` + `naturalize` + habillage séparé | ~45 **CALCULÉ** | ~1,8 s | **~7,5 s** |
| **Fusion + 7 règles de coût** | **3 à 5 CALCULÉ** | 120-200 ms | **0,6 à 0,8 s** |

> 🔒 **Le seul chemin vers 1 s est la fusion.** Toute version « passe séparée »,
> même parfaitement optimisée, reste au-dessus de 2 s : le plafond de
> 12 ms/tick l'interdit arithmétiquement.

C'est la décision D5 (§92), la plus structurante du document.

## §23. Les sept règles de coût

Chacune est mécanique et vérifiable.

### Règle 1 — parcours chunk-majeur

Traiter les 256 colonnes d'un chunk d'affilée. Le chunk et ses sections sont
résolus **une fois pour 256 colonnes** au lieu d'une fois par colonne.

C'est aussi la **condition nécessaire** du court-circuit (§38) : dans l'ordre
actuel de `columnsOf` (`x` externe, `z` interne), on change de chunk tous les
16 pas et on ne peut jamais sauter 256 colonnes d'un coup.

### Règle 2 — lecture par section

Utiliser `readBlock` / `sectionAt` (bloc `T71`, **déjà écrits**). Critère de
recette : le ratio 5/63 doit s'inverser.

### Règle 3 — ne pas matérialiser les colonnes

```java
private static List<int[]> columnsOf(BlockPos min, BlockPos max, int margin) {
    List<int[]> cols = new ArrayList<>();
    for (int x = min.getX() - margin; x <= max.getX() + margin; x++)
        for (int z = min.getZ() - margin; z <= max.getZ() + margin; z++)
            cols.add(new int[]{x, z});
    return cols;
}
```

40 176 tableaux `int[2]` de 16 octets, plus le tableau de pointeurs de
l'`ArrayList` : **~1,3 Mo par appel**, sur **13 sites d'appel** dont plusieurs
exécutés deux fois. Soit **20 à 25 Mo** de déchets par structure, dans une CI
limitée à **2 Go de tas et 2 cœurs**.

Une zone se décrit par `x0, z0, w, h` et un index entier :
`x = x0 + i / h`, `z = z0 + i % h`.

### Règle 4 — une seule `MutableBlockPos` par tranche

`verifyGrassColumn` en alloue une **par colonne** (ligne 3917).

### Règle 5 — biome au niveau de la cellule 4×4

`isSnowy` (ligne 3944) fait une **comparaison de chaînes sur le nom du biome**,
par colonne. Au minimum 16 fois trop souvent, avec le pire outil possible.

### Règle 6 — ne rien écrire quand c'est déjà correct

Comparer avant d'écrire. Sur une zone non remaniée, la grande majorité des
colonnes a déjà le bon bloc de surface. **Un `setBlock` évité est le gain le
plus rentable du lot** — mesure attendue : moins de 10 % des colonnes écrites.

### Règle 7 — `FAST_FLAG`, jamais le flag `3`

Voir §14.

## §24. Que faire si la mesure dépasse 1 s

🔒 **Ne jamais relâcher le seuil.** Deux sorties admises, dans cet ordre :

1. **Réduire le nombre de colonnes.** L'anneau `terrainRing()` est-il justifié
   partout ? ⚠ C'est une **décision de périmètre visible en jeu**, donc à
   soumettre à l'utilisateur (§99).
2. **Augmenter `SLICE_BUDGET_MS`.** Déplace le coût vers le MSPT et risque
   « Can't keep up! ». **À mesurer, jamais à supposer.**

## §25. Rappel de proportion

Répartition mesurée sur le dragon (27/09, total **107,5 s**) :

| Poste | Temps | Part |
|---|---|---|
| `fixLiquids` | 34,3 s | 32 % |
| `preload` | 30,6 s | 29 % |
| `clearSurfaceDecor` | 11,8 s | 11 % |
| balayage des naturels flottants | 9,1 s | 8 % |
| `cleanupZone` | 4,1 s | 4 % |
| hole filler | 4,1 s | 4 % |

**`fixLiquids` + `preload` = 61 % du temps.**

⚠ L'habillage, même à 1 s, **ne fera pas passer le dragon sous 30 s**. Ce budget
est une contrainte de qualité, pas la solution au dépassement. Ne laisse pas ce
chantier masquer la priorité réelle.

# LIVRE IV — LA PALETTE DE SURFACE

## §26. Le problème posé

Après terrassement, le terrain est en pierre et en terre. Quel bloc faut-il
poser en surface ?

Trois réponses possibles, deux mauvaises.

**Mauvaise réponse n°1 : du gazon.** C'est le comportement actuel, et c'est le
bug (§8.1).

**Mauvaise réponse n°2 : demander au biome.** Il n'existe pas d'API (§12.2).

**Bonne réponse : regarder ce qu'il y avait avant, autour.** On échantillonne le
terrain naturel non modifié et on en déduit le bloc dominant.

## §27. Trois erreurs de raisonnement à ne pas refaire

### §27.1 « y0 » n'est pas une altitude constante

Il est tentant d'écrire « le sol est à Y = 64 ». Faux : `y0` est **le premier
bloc solide de chaque colonne**, et il varie d'une colonne à l'autre. Toute
formule qui fixe un Y global produit des terrasses plates ou des colonnes
habillées dans le vide.

### §27.2 Un chunk n'est pas une unité de biome

Voir §12.1. Le chunk est une unité **de palette** — on y échantillonne pour
aller vite — mais **la décision finale est prise par colonne**. Ne jamais
peindre un chunk entier d'un seul bloc sans le tramage du Livre V.

### §27.3 Coiffer un bassin fermé fait un couvercle sur l'eau

Le terrassement crée des cuvettes. Si on habille avant de drainer, on pose une
dalle d'herbe **au-dessus** d'une poche d'eau, et l'eau reste piégée dessous.

🔒 **Le drainage passe avant l'habillage** (invariant I2).

## §28. La méthode d'échantillonnage

- Prendre **16 colonnes témoins** réparties dans le chunk : une grille 4×4 aux
  positions locales **2, 6, 10, 14** (on évite les bords, qui appartiennent
  visuellement au chunk voisin).
- Pour chaque témoin, descendre jusqu'au premier bloc de sol.
- **Traverser sans conclure** : air, eau, neige fine, feuilles, bûches, plantes.
  Ce ne sont pas des blocs de sol.
- **Retenir** le bloc dominant.
- Si moins de **8 témoins sur 16** donnent un résultat, marquer la palette
  **non confiante**.

## §29. Le moment de l'échantillonnage est critique

🔒 **L'échantillonnage doit se faire AVANT toute édition du terrain**, donc au
tout début de `prepZone`, et le résultat **mis en cache** pour toute la durée
de la chaîne.

Si on échantillonne après le lissage, on lit la pierre reconstruite et on obtient
« pierre » partout : la conception s'autodétruit silencieusement — le résultat
est cohérent, juste totalement faux.

**Symptôme de cette erreur :** le log annonce `dominants = stone(289)` et tout
le terrain livré est en pierre. Voir §90.

## §30. Le code complet

```java
// =====================================================================
// PALETTE DE SURFACE
// Echantillonnee AVANT toute edition du terrain (invariant I1).
// Guide : LIVRE IV.
// =====================================================================

/** Palette d'un chunk : bloc de surface dominant + sous-sol associe. */
private record SurfacePalette(Block top, Block filler, int samples, boolean confident) { }

/** Cache par chunk. Vide en fin de chaine, en meme temps que CLEARANCE_PLAN. */
private static final Map<Long, SurfacePalette> PALETTE = new HashMap<>();

/** Compteur de replis, journalise : un taux eleve = echantillonnage trop tardif. */
private static int PALETTE_FALLBACKS = 0;

/** Positions locales des temoins : grille 4x4, evite les bords du chunk. */
private static final int[] WITNESS = { 2, 6, 10, 14 };

/** Nombre minimal de temoins exploitables pour se declarer confiant. */
private static final int PALETTE_MIN_SAMPLES = 8;

/**
 * Echantillonne le sol naturel d'un chunk.
 *
 * A APPELER AVANT TOUTE EDITION : apres le smooth, on ne lirait que la
 * pierre reconstruite et la palette vaudrait « stone » partout.
 */
private static SurfacePalette samplePalette(ServerLevel level, int cx, int cz) {
    long key = net.minecraft.world.level.ChunkPos.asLong(cx, cz);
    SurfacePalette cached = PALETTE.get(key);
    if (cached != null) return cached;

    // Garde-fou : jamais de getChunk sur un chunk absent (theorie, section 11.3).
    if (!deepluckyblock.util.SafeSurface.isLoadedAt(level, cx << 4, cz << 4)) {
        SurfacePalette unknown = new SurfacePalette(Blocks.GRASS_BLOCK, Blocks.DIRT, 0, false);
        PALETTE.put(key, unknown);
        return unknown;
    }

    ChunkAccess chunk = level.getChunk(cx, cz);
    BlockPos.MutableBlockPos mut = new BlockPos.MutableBlockPos();   // UNE pour tout le chunk
    Map<Block, Integer> tally = new HashMap<>();
    int used = 0;
    int floor = level.getMinBuildHeight() + 8;

    for (int lx : WITNESS) {
        for (int lz : WITNESS) {
            int x = (cx << 4) + lx;
            int z = (cz << 4) + lz;
            // Heightmap = BORNE HAUTE uniquement (theorie, section 13).
            int y = deepluckyblock.util.SafeSurface.height(
                    level, Heightmap.Types.MOTION_BLOCKING_NO_LEAVES, x, z) - 1;
            while (y > floor) {
                BlockState s = readBlock(level, chunk, mut, x, y, z);
                if (isGroundCandidate(s)) {
                    tally.merge(s.getBlock(), 1, Integer::sum);
                    used++;
                    break;
                }
                if (!isSkippableCover(s)) break;   // bloc non-sol et non traversable
                y--;
            }
        }
    }

    Block top = Blocks.GRASS_BLOCK;
    int best = 0;
    for (Map.Entry<Block, Integer> e : tally.entrySet())
        if (e.getValue() > best) { best = e.getValue(); top = e.getKey(); }

    SurfacePalette pal = new SurfacePalette(
            top, fillerFor(top), used, used >= PALETTE_MIN_SAMPLES);
    PALETTE.put(key, pal);
    return pal;
}

/** Un bloc qui compte comme « sol » pour la palette. */
private static boolean isGroundCandidate(BlockState s) {
    return s.blocksMotion() && isNaturalTerrain(s)
            && !isLog(s) && !isLeaf(s)
            && !s.is(Blocks.SNOW_BLOCK) && !s.is(Blocks.ICE)
            && !s.is(Blocks.PACKED_ICE) && !s.is(Blocks.BLUE_ICE);
}

/** Couverture a traverser sans conclure : air, eau, neige fine, vegetation. */
private static boolean isSkippableCover(BlockState s) {
    return s.isAir() || s.is(Blocks.WATER) || s.is(Blocks.SNOW)
            || isLeaf(s) || isLog(s) || !s.blocksMotion();
}

/**
 * Palette CONFIANTE la plus proche, recherche en spirale, rayon 3 chunks.
 * C'est cette methode qu'on appelle partout, jamais samplePalette directement.
 */
private static SurfacePalette paletteAt(ServerLevel level, int cx, int cz) {
    SurfacePalette p = samplePalette(level, cx, cz);
    if (p.confident()) return p;
    for (int r = 1; r <= 3; r++)
        for (int dx = -r; dx <= r; dx++)
            for (int dz = -r; dz <= r; dz++) {
                if (Math.max(Math.abs(dx), Math.abs(dz)) != r) continue;   // anneau seul
                SurfacePalette q = samplePalette(level, cx + dx, cz + dz);
                if (q.confident()) { PALETTE_FALLBACKS++; return q; }
            }
    return p;   // rien de confiant a 3 chunks : on garde le defaut
}
```

## §31. Le sous-sol

```java
/**
 * Sous-sol associe a une surface.
 * null = SOL INCONNU (modde) : on pose la surface et on ne touche pas dessous.
 */
private static Block fillerFor(Block top) {
    if (top == Blocks.SAND)          return Blocks.SANDSTONE;
    if (top == Blocks.RED_SAND)      return Blocks.RED_SANDSTONE;
    if (top == Blocks.GRASS_BLOCK)   return Blocks.DIRT;
    if (top == Blocks.PODZOL)        return Blocks.DIRT;
    if (top == Blocks.MYCELIUM)      return Blocks.DIRT;
    if (top == Blocks.COARSE_DIRT)   return Blocks.DIRT;
    if (top == Blocks.MOSS_BLOCK)    return Blocks.DIRT;
    if (top == Blocks.GRAVEL)        return Blocks.STONE;
    if (top == Blocks.SNOW_BLOCK)    return Blocks.DIRT;
    return null;                      // inconnu : CONSERVER l'existant
}
```

`SUBSOIL_DEPTH = 3` : une surface plus trois blocs de sous-sol. Sans cela, la
pierre apparaît au premier coup de pioche ou dès la première pente marquée.

⚠ Le repli `null` est important. Pour un sol moddé qu'on ne connaît pas, poser
un sous-sol arbitraire serait pire que de ne rien faire.

- `0 repli` : tous les chunks ont eu au moins 8 témoins. Sain.
- `sand(271)` sur un désert : correct.
- `stone(289)` : ⚠ l'échantillonnage a eu lieu **après** le terrassement.
  Voir §29.
- un taux de repli élevé : même cause, ou zone majoritairement océanique.

# LIVRE V — LE DÉGRADÉ ENTRE DEUX SOLS

C'est la partie la plus délicate du système, et celle qui a demandé le plus de
corrections. Lis-la en entier avant d'écrire une ligne.

## §33. Pourquoi un dégradé, et pourquoi pas un mélange

Un bloc est sable **ou** gazon. Il n'y a rien à interpoler. La seule façon de
simuler une transition est le **tramage** : plus on s'approche du voisin, plus
la probabilité de poser **son** bloc est grande.

C'est exactement ce que fait le mod **Pufferfish's Biome Dither** : l'approche
est validée par l'usage, pas inventée ici.

## §34. Le principe de base

```java
bloc = (posNoise(x, z, SALT_GROUND) < p) ? blocVoisin : blocLocal;
```

avec `p` fonction de la distance à la frontière.

🔒 **Jamais `level.getRandom()`** (voir §18).

## §35. La table de probabilité

| Distance au bord | p (probabilité de prendre le bloc voisin) |
|---|---|
| 5 | 10 % |
| 4 | 20 % |
| 3 | 30 % |
| 2 | 40 % |
| 1 | 50 % |

```
chunk GAZON          |          chunk SABLE
                     |
  ...  G  G  G  G  G | S  S  S  S  S  ...
distance au bord :
        5  4  3  2  1 | 1  2  3  4  5
p(prendre l'autre) :
       10 20 30 40 50 |50 40 30 20 10   (%)
                     ^
              la frontiere est a 50/50 des DEUX cotes
              -> aucune couture visible
```

La série est **symétrique** : les deux côtés se rejoignent à 50/50.

**Réserve mesurée :** le mélange de biomes vanilla côté client va jusqu'à
**7 blocs**, le mod « Better Biome Blend » jusqu'à **15**. Une bande de 5 est
plutôt courte. Candidat A/B, voir §100.

## §36. ⚠ Le piège des angles

Une colonne d'angle a **trois** voisins pertinents : gauche, haut, diagonal.

Appliquer deux règles successives (« d'abord la règle ouest, puis la règle
nord ») est **faux** : la seconde écrase la première et le coin penche
visiblement d'un côté.

### Démonstration chiffrée

Chunk de **sable**, voisin ouest **gazon**, voisin nord **gravier**, colonne
locale `lx = 1, lz = 2` (donc à 2 blocs du bord ouest, 3 du bord nord).

| | distance | p |
|---|---|---|
| ouest (gazon) | 2 | 40 % |
| nord (gravier) | 3 | 30 % |
| **local (sable)** | — | **30 %** |

`total = 0,70 ≤ 1`, pas de renormalisation. **Un seul tirage** `r ∈ [0,1)` :

- `r < 0,40` → gazon
- `0,40 ≤ r < 0,70` → gravier
- `r ≥ 0,70` → sable

**Avec deux règles successives**, on tirerait d'abord gazon à 40 %, puis
gravier à 30 % **sur le résultat** : 40 % × 70 % = **28 % de gazon** contre
30 % de gravier. Le coin penche vers le nord.

C'est un bug qu'on ne voit qu'en jeu et qu'on ne relie jamais à sa cause.

🔒 **Un seul tirage pondéré, avec `p_local = 1 − Σ p_voisins`.**

## §37. ⚠ Comparer `Block`, jamais `BlockState`

`Blocks.GRASS_BLOCK.defaultBlockState()` et le même état avec `snowy=true` sont
deux `BlockState` différents pour le **même** `Block`.

Comparer les `BlockState` déclencherait un mélange entre variantes du même
bloc : coût inutile et résultat incohérent. Invariant I4.

## §38. LE COURT-CIRCUIT — règle de conception, pas optimisation tardive

> **Si deux chunks voisins ont la même palette, il n'y a rien à mélanger.**
> Calculer un tramage entre du sable et du sable est du travail pur perdu.

### §38.1 Trois niveaux

**Niveau 1 — chunk entier.** Les 8 voisins ont la même palette : remplir les 256
colonnes avec le bloc local. **Aucun hash, aucune lecture de voisin.** C'est le
cas courant en plein désert ou en pleine plaine.

**Niveau 2 — par côté.** Marquer chaque côté identique/différent **une seule
fois**, au moment du calcul de la palette du chunk. Les côtés identiques ne
génèrent aucune bande.

**Niveau 3 — par colonne.** Aucun voisin différent à portée → bloc local, pas de
tirage.

### §38.2 Cohérence avec le tirage d'angle

Le tirage pondéré ne porte que sur les voisins **réellement différents** :

- un seul voisin différent → on retombe exactement sur la table 10/20/30/40/50 % ;
- zéro voisin différent → pas de tirage du tout.

### §38.3 Le court-circuit est aussi un test de correction

Le coût doit être proportionnel au **nombre de frontières**, pas au nombre de
colonnes.

🔒 **Journaliser « chunks en chemin rapide » contre « chunks mélangés ».** Un
désert qui affiche beaucoup de chunks mélangés signale une **palette fausse** :
l'optimisation sert de détecteur de bug.

### §38.4 Dépendance à l'ordre de parcours

Le niveau 1 n'a d'effet **que** si le parcours est **chunk-majeur** (règle 1 du
§23). Les deux vont ensemble.

### §38.5 Mesure

Sur la grille de référence 3×3 du §41 : **387 colonnes sur 2 304 modifiées par
le tramage, soit 16,8 %**. Les **83,2 % restants passent par le chemin rapide**.
C'est le chiffre qui justifie le court-circuit.

## §39. Le hash de position

```java
/** Sels distincts : reutiliser le meme aligne les plantes sur le sol. */
private static final int SALT_GROUND = 0x51D0;
private static final int SALT_PLANT  = 0x91A7;
private static final int SALT_PICK   = 0x3C29;
private static final int SALT_STACK  = 0x7B41;
private static final int SALT_WARP   = 0x6A19;

/** Hash de position -> [0,1). Deterministe, sans allocation. */
private static float posNoise(int x, int z, int salt) {
    int h = x * 0x27d4eb2d ^ z * 0x85ebca6b ^ salt * 0x165667b1;
    h ^= h >>> 15; h *= 0x2545f491; h ^= h >>> 13;
    return (h & 0x00ffffff) / (float) 0x01000000;
}
```

⚠ **Un sel différent par usage.** Avec le même sel, les plantes s'alignent
exactement sur les motifs du sol et le résultat paraît artificiel.

| Test | Résultat | Verdict |
|---|---|---|

| Écart-type global | 0,2889 (attendu 0,2887) | sain |

## §40. Le code du tirage

```java
/** Largeur de la bande de transition, en blocs. */
private static final int BLEND_BAND = 5;

/** Probabilite de prendre le voisin, selon la distance au bord. */
private static float edgeP(int distance) {
    if (distance <= 0 || distance > BLEND_BAND) return 0f;
    return (BLEND_BAND + 1 - distance) * 0.5f / BLEND_BAND;   // 1 -> 50%, 5 -> 10%
}

/**
 * UN SEUL tirage sur TOUS les voisins reellement differents.
 * Deux regles sequentielles donneraient un coin penche (section 36) : interdit.
 */
private static Block pickGround(SurfacePalette local, SurfacePalette[] nb,
                                int x, int z, int lx, int lz) {
    // Indices NOMMES. L'ordre de remplissage est dx = -1..1 puis dz = -1..1,
    // centre exclu, donc :
    //   0 (-1,-1)   1 (-1, 0) OUEST   2 (-1,+1)
    //   3 ( 0,-1) NORD                4 ( 0,+1) SUD
    //   5 (+1,-1)   6 (+1, 0) EST     7 (+1,+1)
    // Une premiere redaction utilisait nb[7] pour l'EST : c'est le voisin
    // diagonal sud-est. NE JAMAIS ecrire ces indices a la main.
    final int W = 1, N = 3, S = 4, E = 6;

    // Distances PERTURBEES (section 43), un sel par cote.
    float dW = effectiveDistance(lx + 1,  x, z, SALT_WARP);
    float dE = effectiveDistance(16 - lx, x, z, SALT_WARP + 1);
    float dN = effectiveDistance(lz + 1,  x, z, SALT_WARP + 2);
    float dS = effectiveDistance(16 - lz, x, z, SALT_WARP + 3);

    float pWest  = nb[W] != null ? edgeP(Math.round(dW)) : 0f;
    float pEast  = nb[E] != null ? edgeP(Math.round(dE)) : 0f;
    float pNorth = nb[N] != null ? edgeP(Math.round(dN)) : 0f;
    float pSouth = nb[S] != null ? edgeP(Math.round(dS)) : 0f;

    float total = pWest + pEast + pNorth + pSouth;
    if (total <= 0f) return local.top();       // niveau 3 du court-circuit
    if (total > 1f) {                           // coin : renormalisation
        pWest /= total; pEast /= total; pNorth /= total; pSouth /= total;
        total = 1f;
    }

    float r = posNoise(x, z, SALT_GROUND);
    if (r < pWest)                   return nb[W].top();
    if (r < pWest + pEast)           return nb[E].top();
    if (r < pWest + pEast + pNorth)  return nb[N].top();
    if (r < total)                   return nb[S].top();
    return local.top();
}
```

## §42. ⚠ Le défaut de l'enveloppe rectiligne

Défaut signalé à la relecture : « le dégradé se répète sur 5 lignes avec les
mêmes motifs de blocs ».

**Le symptôme est réel. La cause n'est pas le hash** (§39.1 le mesure).

> **La bande de transition est un couloir rectiligne de 10 blocs de large
> (5 + 5), parfaitement aligné sur la grille des chunks, et son profil de
> probabilité 10/20/30/40/50 % est identique sur toute sa longueur.**

Le **contenu** de la bande est aléatoire, mais **son contour ne l'est pas**.
L'œil humain détecte très bien une frontière droite de largeur constante : il
reconstruit la grille 16×16 à partir de l'enveloppe, même quand chaque bloc pris
isolément est imprévisible. C'est le même carré de chunk qu'au départ, juste
flouté.

Et c'est bien « les mêmes motifs sur 5 lignes » : à chaque rangée, les mêmes cinq
probabilités dans le même ordre, sur la même colonne de blocs.

## §43. Le correctif : perturber la frontière (domain warping)

![Bande droite contre bande perturbée](docs/images/transition-bande-perturbee.png)

On décale la **distance au bord** par un bruit de valeur basse fréquence. La
frontière serpente alors à travers les chunks au lieu de suivre leurs arêtes.

```java
private static final int   WARP_CELL = 12;    // taille de cellule du bruit, en blocs
private static final float WARP_AMP  = 4.0f;  // amplitude du serpentement, en blocs

private static float smoothstep(float t) { return t * t * (3f - 2f * t); }

/** Bruit de valeur 2D interpole -- basses frequences, sans allocation. */
private static float valueNoise(int x, int z, int cell, int salt) {
    int gx = Math.floorDiv(x, cell), gz = Math.floorDiv(z, cell);
    float fx = smoothstep(Math.floorMod(x, cell) / (float) cell);
    float fz = smoothstep(Math.floorMod(z, cell) / (float) cell);
    float n00 = posNoise(gx,     gz,     salt), n10 = posNoise(gx + 1, gz,     salt);
    float n01 = posNoise(gx,     gz + 1, salt), n11 = posNoise(gx + 1, gz + 1, salt);
    return (n00 * (1 - fx) + n10 * fx) * (1 - fz) + (n01 * (1 - fx) + n11 * fx) * fz;
}

/** Distance au bord PERTURBEE : la frontiere serpente au lieu d'etre droite. */
private static float effectiveDistance(int d, int x, int z, int salt) {
    return d - (valueNoise(x, z, WARP_CELL, salt) - 0.5f) * 2f * WARP_AMP;
}
```

⚠ **Un sel différent par côté**, sinon les quatre frontières d'un chunk
ondulent en phase et recréent un motif.

### §43.1 La contrainte à respecter

> 🔒 **`WARP_AMP + BLEND_BAND ≤ 16`**

Au-delà, la bande d'un chunk déborderait sur le chunk d'après-voisin, dont la
palette n'est pas lue (on ne regarde que les 8 voisins immédiats). Avec
`BLEND_BAND = 5`, l'amplitude maximale est **11** ; la valeur retenue de **4**
laisse une marge confortable.

### §43.2 Limite honnête

Le serpentement reste **borné par le chunk**. La frontière n'est plus droite,
mais elle ne peut pas s'éloigner de plus de 4 blocs de l'arête. Pour un contour
vraiment libre, il faudrait lire les palettes sur un rayon de **2 chunks**, ce
qui multiplie par ~2,8 le nombre de palettes consultées. **SUPPOSÉ** : le
court-circuit en absorberait le coût, la plupart des voisins étant identiques.
**Non démontré — à mesurer avant de le faire.**

### §43.3 Coût

Une lecture de `valueNoise` par colonne **de bande uniquement**, soit sur les
16,8 % de colonnes qui ne passent pas par le chemin rapide. Quatre appels à
`posNoise` et deux interpolations. Négligeable devant les 6 µs/colonne du
budget. **Le chemin rapide n'est pas touché.**

## §44. A/B n°2 : hash contre tramage ordonné — TRANCHÉ

![A/B hash contre Bayer](docs/images/ab-tramage-hash-vs-bayer.png)

**Résultat : le hash est conservé. Le tramage ordonné est rejeté.** Ce test est
clos ; ne pas le rouvrir sans lire cette section.

### §44.1 Une auto-correction de méthode

Une première mesure, sur **16 colonnes**, donnait au hash une erreur de
15,5 points et concluait en faveur de Bayer. **C'était un artefact
d'échantillonnage** : à n = 16 et p = 0,3, l'écart-type binomial est de
**±11,5 points**, soit plus que l'effet cherché.

Refaite sur **1 024 blocs de frontière** :

| mode | erreur de fidélité | irrégularité locale | motifs distincts / 256 |
|---|---|---|---|
| **hash** | **0,68 point** | 0,130 | **25** |
| Bayer 4×4 | 6,00 points | 0,060 | **4** |
| Bayer 8×8 | 6,00 points | 0,060 | **4** |
| hybride (gigue 0,125) | 9,57 points | 0,094 | 4 |
| hybride (gigue 0,25) | 10,36 points | 0,112 | 8 |
| hybride (gigue 0,50) | 8,97 points | 0,121 | 14 |
| hybride (gigue 0,75) | 4,79 points | 0,111 | 19 |
| hybride (gigue 1,00) | 2,61 points | 0,115 | 20 |

### §44.2 Pourquoi Bayer est structurellement inadapté

Ce n'est pas un problème de réglage, c'est géométrique.

> La probabilité varie **le long de l'axe perpendiculaire à la frontière**, qui
> est **aussi un axe de la matrice de Bayer**. À distance fixe, on ne voit donc
> qu'une seule ligne de la matrice, et les seuils se quantifient.

| distance | consigne | Bayer obtient |
|---|---|---|
| 1 | 50 % | 50 % |
| 2 | 40 % | **50 %** |
| 3 | 30 % | **25 %** |
| 4 | 20 % | **25 %** |
| 5 | 10 % | **0 %** |

**La rangée la plus externe est toujours vide** : la bande annoncée à 5 blocs
n'en fait réellement que 4, et se termine par une marche nette — le défaut même
qu'on cherchait à supprimer. Passer en 8×8 ne change rien : le problème est
l'alignement des axes, pas la finesse de la matrice.

Second défaut, visible sur l'image : **4 motifs de colonne distincts sur 256**.
La frontière se répète tous les 4 blocs. À l'œil, un damier régulier — plus
artificiel qu'une frontière franche.

### §44.3 Les hybrides ne sauvent rien

Le tableau est monotone : plus la gigue augmente, plus la fidélité s'améliore et
plus le nombre de motifs croît — **c'est-à-dire plus le résultat converge vers
le hash pur**. Aucun réglage intermédiaire ne bat le hash sur les deux critères.
Il n'y a pas de compromis à trouver : il y a un gagnant.

### §44.4 Ce que le hash concède

Le hash est **deux fois plus irrégulier localement** que Bayer (0,130 contre
0,060). C'est le prix de l'absence de motif : des paquets de 5 à 7 blocs de même
couleur au lieu de 5. Sur du sol naturel, cela ressemble davantage à de la
nature qu'à un damier.

# LIVRE VI — LA VÉGÉTATION

## §45. La règle fondamentale

🔒 **C'est le bloc de surface FINAL qui décide de la végétation.** Jamais le
biome seul, jamais l'ancien sol, jamais la palette théorique du chunk.

C'est pour cela que la végétation doit être décidée **dans la même descente de
colonne** que l'habillage : à ce moment-là, et seulement à ce moment-là, on
connaît le bloc réellement posé.

## §46. `canSurvive` remplace la table sol↔plante

La conception initiale prévoyait une table « quel sol accepte quelle plante ».
**Elle est inutile et nuisible** : elle ne couvre ni les règles d'adjacence du
cactus, ni les plantes de mods.

```java
/**
 * Une plante peut-elle vivre ici ? On pose la question au bloc lui-meme.
 * Couvre le cactus (sable + cotes libres), la canne a sucre (sol valide +
 * eau adjacente), le buisson mort (tag), et toutes les plantes moddees.
 */
private static boolean canPlant(LevelReader level, BlockPos pos, BlockState plant) {
    return level.getBlockState(pos).isAir() && plant.canSurvive(level, pos);
}
```

⚠ Voir §16 pour le piège de la lumière en worldgen.

## §47. La pose

```java
/**
 * Pose une plante ordinaire si le sol final l'accepte.
 * La decision vient du BLOC DE SURFACE FINAL, jamais du biome.
 */
private static boolean plantOn(ServerLevel level, BlockPos.MutableBlockPos mut,
                               int x, int surfY, int z, Block ground, long vegSeed) {
    float r = posNoise(x, z, SALT_PLANT);
    if (r > densityFor(ground)) return false;

    BlockState plant = pickPlant(ground, posNoise(x, z, SALT_PICK));
    if (plant == null) return false;

    mut.set(x, surfY + 1, z);
    if (!level.getBlockState(mut).isAir()) return false;
    if (!plant.canSurvive(level, mut)) return false;      // LA verification

    level.setBlock(mut, plant, FAST_FLAG);
    return true;
}
```

`densityFor` et `pickPlant` restent des tables — mais des tables **de goût**
(combien, lesquelles), pas **de validité**. La validité est tranchée par
`canSurvive`. C'est toute la différence avec la conception initiale.

Exemple de table de densité, à ajuster :

| Sol | densité | espèces typiques |
|---|---|---|
| `GRASS_BLOCK` | 0,30 | herbes, fougères, fleurs |
| `PODZOL` | 0,20 | fougères, champignons |
| `MYCELIUM` | 0,15 | champignons |
| `SAND` | 0,02 | buisson mort, cactus (par le sauvetage) |
| `RED_SAND` | 0,02 | buisson mort |
| `GRAVEL` | 0,00 | rien |
| `SNOW_BLOCK` | 0,00 | rien |
| inconnu | 0,00 | rien — 🔒 ne jamais deviner |

## §48. Option : laisser le biome décider

Plutôt qu'une table, on peut rejouer ce que le biome pose lui-même :

```java
var settings = biome.value().getGenerationSettings();
var vegetal  = settings.features()
        .get(GenerationStep.Decoration.VEGETAL_DECORATION.ordinal());   // ordinal 9
for (Holder<PlacedFeature> h : vegetal) {
    h.value().place(level, level.getChunkSource().getGenerator(), random, pos);
}
```

C'est exactement ce que fait la commande `/place feature`.
`ServerLevel implements WorldGenLevel`, donc la signature passe.

**Bonne nouvelle :** les avertissements de « feature cycle violation » ne
concernent que les ajouts par `BiomeModifier`, **pas** les appels directs à
`PlacedFeature.place`.

⚠ **Limite honnête :** une `PlacedFeature` embarque ses propres modificateurs
de placement (`CountPlacement`, `RarityFilter`, `InSquarePlacement`…).
`place()` **ne garantit pas** une pose à la position demandée : la feature peut
se disperser ailleurs dans le chunk, ou ne rien poser. **Mesurer la densité
obtenue**, ne jamais supposer « un appel = une plante ».

**Recommandation :** commencer par la table (§47), qui est prévisible et
mesurable. Garder l'approche par features comme candidat A/B n°3 (§100).

# LIVRE VII — LE SAUVETAGE DES PLANTES NON COUVERTES

## §49. Le besoin

`naturalize` sait reposer les herbes, les fleurs et les champignons.
**Tout le reste disparaît** quand le terrain est remodelé : cactus, canne à
sucre, bambou, buissons morts, baies, plantes doubles (tournesol, lilas, grande
fougère), et **toutes les plantes moddées** qui ne sont ni dans
`#minecraft:flowers` ni des `MushroomBlock`.

Le mod scanne déjà toute la zone pour sauver les arbres (`scanTrees`,
ligne 1273). **On greffe la détection des plantes sur ce scan** : mêmes
colonnes, même descente, **aucune passe supplémentaire** (invariant I5).

## §50. Les trois principes

> **1. Ne mémoriser que ce que `naturalize` ne sait pas refaire.** Les herbes et
> fleurs vanilla sont déjà générées procéduralement : les stocker serait un
> gaspillage pur de mémoire.
>
> **2. Ne pas mémoriser les positions.** On ne repose pas une plante là où elle
> était — le terrain a changé. On mémorise un **inventaire par chunk** : « ce
> chunk contenait 12 cannes à sucre et 4 cactus ». C'est deux ordres de grandeur
> plus léger que `SavedTree`.
>
> **3. Ne jamais poser sans vérifier les conditions**, qui sont parfois non
> triviales (§52).

## §51. L'ensemble connu, calculé à l'exécution

Vérifié dans le code (`scanFlowers` 4580, `scanMushrooms` 4628,

```java
private static Set<Block> KNOWN_BY_NATURALIZE = null;

private static Set<Block> knownByNaturalize() {

    known.add(Blocks.TALL_GRASS);
```

## §52. Les contraintes de pose, plante par plante

| Plante | Contrainte | Qui la vérifie |
|---|---|---|
| **Cactus** | sur `SAND`, `RED_SAND`, `SUSPICIOUS_SAND` ou un autre cactus ; **casse si l'un des 4 blocs latéraux est solide ou de la lave** ; casse si le bloc au-dessus est de l'eau ou de la lave | `canSurvive` **+ pose en dernier** |
| **Canne à sucre** | sur `GRASS_BLOCK`, `DIRT`, `COARSE_DIRT`, `ROOTED_DIRT`, `PODZOL`, `MYCELIUM`, `SAND`, `RED_SAND`, `MOSS_BLOCK`, `MUD` — **et le support doit toucher l'eau sur l'un des 4 côtés**, pas en diagonale, pas au-dessus | `canSurvive` |
| **Bambou** | sol sable/terre ; pousse en colonne | `canSurvive` |
| **Buisson mort** | tag `dead_bush_may_place_on` (⚠ nom de 1.21.1, §17) | `canSurvive` |
| **Nénuphar** | sur une source d'eau, air au-dessus | `canSurvive` |
| **Plantes doubles** | **2 blocs** : `HALF=LOWER` puis `HALF=UPPER` | pose spéciale |
| **Lianes / murales** | support latéral | **non sauvé** |
| **Spore blossom** | plafond | **non sauvé** |
| **Aquatiques** (kelp, algues) | dans l'eau, `waterlogged` | **non sauvé** |

### §52.1 Décision explicite : seulement les plantes de sol

Les plantes de mur, de plafond et d'eau sont **ignorées à la détection**. Les
reposer demanderait un modèle de support totalement différent, et
`sweepFloatingDecor` les retire déjà proprement. **Limite assumée, pas oubli.**

### §52.2 ⚠ Le piège du cactus différé

> **Le cactus peut être valide au moment de la pose et casser ensuite**, dès
> qu'un bloc solide apparaît à côté. Il ne suffit pas que `canSurvive` réponde
> oui : il faut que **plus rien ne soit posé à côté après**.

D'où l'ordre du §55.

### §52.3 ⚠ Le piège de la plante double

Poser la moitié basse avec mise à jour de voisinage **la casse aussitôt**,
faute de moitié haute. `FAST_FLAG` contient le bit 16 (pas de mise à jour) :
avec lui, l'ordre des deux moitiés est indifférent. **Sans lui, rien ne tient.**

```java
/** Une plante de SOL que naturalize ne sait pas refaire. */
private static boolean isRescuable(BlockState s) {
    Block b = s.getBlock();
    if (knownByNaturalize().contains(b)) return false;      // deja couvert
    if (!isGroundPlant(s)) return false;                    // mur / plafond / eau
    // Moities HAUTES des plantes doubles : on ne compte que la moitie basse,
    // sinon chaque tournesol serait compte DEUX fois.
    if (b instanceof net.minecraft.world.level.block.DoublePlantBlock
            && s.getValue(net.minecraft.world.level.block.DoublePlantBlock.HALF)
               == net.minecraft.world.level.block.state.properties.DoubleBlockHalf.UPPER)
        return false;
    return true;
}

/** Plante qui pousse sur le sol (par opposition a mur / plafond / eau). */
private static boolean isGroundPlant(BlockState s) {
    if (!s.getFluidState().isEmpty()) return false;                  // aquatique
    if (s.is(net.minecraft.tags.BlockTags.CLIMBABLE)) return false;  // lianes, echelles
    Block b = s.getBlock();
    if (b == Blocks.SPORE_BLOSSOM || b == Blocks.HANGING_ROOTS) return false;
    if (b == Blocks.CACTUS || b == Blocks.SUGAR_CANE || b == Blocks.BAMBOO
            || b == Blocks.DEAD_BUSH || b == Blocks.SWEET_BERRY_BUSH) return true;
    if (b instanceof net.minecraft.world.level.block.DoublePlantBlock) return true;
    // Cas general, couvre les mods : une BushBlock se pose sur un sol.
    return b instanceof net.minecraft.world.level.block.BushBlock;
}

/** Comptabilise, avec les deux plafonds de securite. */
private static void noteRescue(int x, int z, BlockState s) {
    if (rescueTotal >= RESCUE_MAX_TOTAL) return;
    long key = net.minecraft.world.level.ChunkPos.asLong(x >> 4, z >> 4);
    Map<Block, Integer> inv = RESCUE.computeIfAbsent(key, k -> new HashMap<>());
    int already = 0;
    for (int v : inv.values()) already += v;
    if (already >= RESCUE_MAX_PER_CHUNK) return;
    inv.merge(s.getBlock(), 1, Integer::sum);
    rescueTotal++;
}
```

**Pourquoi `BushBlock` comme filet général :** en 1.21.1, la quasi-totalité des
plantes de sol — vanilla comme moddées — en hérite. C'est la façon la plus large
d'attraper les plantes de mods sans liste en dur. Les mods enregistrent leurs
blocs dans `BuiltInRegistries.BLOCK` comme vanilla, donc le test fonctionne sans
configuration.

## §55. La repose

```java
/**
 * Repose les plantes sauvees du chunk, a des emplacements VALIDES,
 * pas a leur position d'origine (le terrain a change).
 * Appelee a la fin du traitement d'un chunk par dressAndPlant.
 */
private static int replantRescued(ServerLevel level, ChunkAccess chunk,
                                  BlockPos.MutableBlockPos mut, int cx, int cz,
                                  int[] surfCache) {
    long key = net.minecraft.world.level.ChunkPos.asLong(cx, cz);
    Map<Block, Integer> inv = RESCUE.get(key);
    if (inv == null || inv.isEmpty()) return 0;

    // Le CACTUS passe en DERNIER : il casse si un bloc solide apparait a cote
    // apres sa pose (guide, section 52.2).
    List<Map.Entry<Block, Integer>> ordered = new ArrayList<>(inv.entrySet());
    ordered.sort((a, b) -> Boolean.compare(a.getKey() == Blocks.CACTUS,
                                           b.getKey() == Blocks.CACTUS));

    int placed = 0;
    for (Map.Entry<Block, Integer> e : ordered) {
        Block plant = e.getKey();
        int wanted = e.getValue();
        int tries = 0;
        // Ordre de visite DETERMINISTE mais disperse : permutation issue du hash,
        // pas un parcours en ligne (sinon toutes les plantes s'alignent).
        for (int n = 0; n < 256 && wanted > 0 && tries < RESCUE_MAX_TRIES; n++) {
            int idx = scramble(n, cx, cz);          // 0..255, bijection
            int lx = idx & 15, lz = idx >> 4;
            int x = (cx << 4) + lx, z = (cz << 4) + lz;
            int surfY = surfCache[idx];
            if (surfY < 1) continue;
            tries++;
            if (tryPlaceRescued(level, mut, plant, x, surfY, z)) { wanted--; placed++; }
        }
    }
    RESCUE.remove(key);
    return placed;
}

private static final int RESCUE_MAX_TRIES = 512;

/** Permutation bijective de 0..255, deterministe par chunk. */
private static int scramble(int n, int cx, int cz) {
    int k = (int) (posNoise(cx, cz, 0x2C1B) * 251) | 1;   // impair -> bijection
    return (n * k + (cx * 7 + cz * 13)) & 255;
}
```

**MESURÉ :** `scramble` est bien une bijection de 0..255 sur les
**6 400 chunks** testés (`docs/images/ab_tramage.py`, test 4). Le `| 1` est ce
qui le garantit : `n·k mod 256` est bijectif si et seulement si `k` est impair.

```java
/** Pose une plante sauvee si l'emplacement la supporte. Gere piles et doubles. */
private static boolean tryPlaceRescued(ServerLevel level, BlockPos.MutableBlockPos mut,
                                       Block plant, int x, int surfY, int z) {
    mut.set(x, surfY + 1, z);
    if (!level.getBlockState(mut).isAir()) return false;

    BlockState base = plant.defaultBlockState();
    // LA verification : couvre cactus (sable + cotes libres), canne a sucre
    // (sol valide + eau adjacente), buisson mort (tag), bambou, plantes moddees.
    if (!base.canSurvive(level, mut)) return false;

    // --- PLANTE DOUBLE : deux blocs, moitie BASSE puis HAUTE.
    if (plant instanceof net.minecraft.world.level.block.DoublePlantBlock) {
        mut.set(x, surfY + 2, z);
        if (!level.getBlockState(mut).isAir()) return false;
        // FAST_FLAG (bit 16 = pas de mise a jour de voisinage) : sans lui, poser
        // la moitie basse declenche une mise a jour qui la casse aussitot.
        level.setBlock(mut.set(x, surfY + 1, z), base.setValue(
                net.minecraft.world.level.block.DoublePlantBlock.HALF,
                net.minecraft.world.level.block.state.properties.DoubleBlockHalf.LOWER),
                FAST_FLAG);
        level.setBlock(mut.set(x, surfY + 2, z), base.setValue(
                net.minecraft.world.level.block.DoublePlantBlock.HALF,
                net.minecraft.world.level.block.state.properties.DoubleBlockHalf.UPPER),
                FAST_FLAG);
        return true;
    }

    // --- PLANTE EN PILE : cactus, canne a sucre, bambou.
    //     Hauteur deterministe, jamais au-dela de la hauteur naturelle.
    int height = 1;
    if (plant == Blocks.CACTUS || plant == Blocks.SUGAR_CANE)
        height = 1 + (int) (posNoise(x, z, SALT_STACK) * 3);        // 1..3
    else if (plant == Blocks.BAMBOO)
        height = 2 + (int) (posNoise(x, z, SALT_STACK) * 6);        // 2..7

    for (int h = 0; h < height; h++) {
        mut.set(x, surfY + 1 + h, z);
        if (!level.getBlockState(mut).isAir()) break;
        level.setBlock(mut, base, FAST_FLAG);
    }
    return true;
}
```

**MESURÉ :** la distribution des hauteurs 1/2/3 sur 40 000 positions est
13 375 / 13 320 / 13 305, soit très exactement un tiers chacune.

## §56. L'ordre de pose global

Le cactus casse si un bloc solide apparaît sur l'un de ses 4 côtés **après** sa
pose. Il faut donc que plus rien ne soit posé à côté ensuite :

1. habillage du sol ;
2. végétation ordinaire ;
3. décors dispersés (`StructureScatterDecor.scatter`) ;
4. arbres replantés (`replantTrees`) ;
5. **plantes sauvées non-cactus** ;
6. **cactus en tout dernier**.

En pratique : `replantRescued` trie son inventaire pour traiter `CACTUS` à la
fin, et n'est appelée qu'après `scatter` et `replantTrees`.

## §57. Coût

| Poste | Coût |
|---|---|
| Détection | **un test de `Set` sur un bloc déjà lu**, dans une boucle existante. Zéro colonne, zéro descente en plus. |
| Mémoire | une entrée `(Block, int)` par espèce et par chunk, plafonnée à 64/chunk et 20 000 au total. |
| Repose | bornée à **512 essais par espèce et par chunk**, sur des colonnes dont le `surfY` est **déjà en cache**. |

Le système **ne peut pas** faire déborder le budget de 1 s : il n'ajoute ni
passe, ni descente de colonne, et sa borne d'essais est dure.

## §59. Le parcours chunk-majeur, sans allocation

```java
/**
 * Zone rectangulaire parcourue CHUNK PAR CHUNK, sans materialiser les colonnes.
 * Remplace columnsOf() : 0 allocation contre ~1,3 Mo par appel.
 */
private static final class ChunkMajorZone {
    final int x0, z0, x1, z1;          // bornes INCLUSIVES, en blocs
    final int cx0, cz0, cx1, cz1;      // bornes en chunks
    final int chunksZ, chunkCount;

    ChunkMajorZone(BlockPos min, BlockPos max, int margin) {
        this.x0 = min.getX() - margin; this.z0 = min.getZ() - margin;
        this.x1 = max.getX() + margin; this.z1 = max.getZ() + margin;
        this.cx0 = x0 >> 4; this.cz0 = z0 >> 4;
        this.cx1 = x1 >> 4; this.cz1 = z1 >> 4;
        this.chunksZ = cz1 - cz0 + 1;
        this.chunkCount = (cx1 - cx0 + 1) * chunksZ;
    }

    int chunkX(int i) { return cx0 + i / chunksZ; }
    int chunkZ(int i) { return cz0 + i % chunksZ; }

    /** true si le chunk i est entierement a l'interieur de la zone. */
    boolean chunkFullyInside(int i) {
        int bx = chunkX(i) << 4, bz = chunkZ(i) << 4;
        return bx >= x0 && bz >= z0 && bx + 15 <= x1 && bz + 15 <= z1;
    }

    boolean contains(int x, int z) {
        return x >= x0 && x <= x1 && z >= z0 && z <= z1;
    }

    int columns() { return (x1 - x0 + 1) * (z1 - z0 + 1); }
}
```

La passe avance **par chunk**, pas par colonne : le curseur est un index de
chunk. Un chunk = 256 colonnes ; avec `SLICE_BUDGET_MS = 12` et 5 µs/colonne,
cela fait **~9 chunks par tranche**. Le grain reste assez fin pour ne pas
dépasser le budget d'un tick.

## §60. La passe par chunk

```java
private interface ChunkAction { void run(int chunkIndex); }

/**
 * Variante chunk-majeure de startColumnPass. Memes garde-fous :
 * ChunkKeeper.keep, TerrainChain.heartbeat, report si zone incomplete,
 * budget adaptatif, garde anti-doublon.
 */
private static void startChunkPass(ServerLevel level, String label,
                                   ChunkMajorZone zone, ChunkAction action,
                                   Runnable onDone) {
    if (zone.chunkCount <= 0) { if (onDone != null) onDone.run(); return; }
    if (!RUNNING_PASSES.add(label)) {
        deepluckyblock.util.DebugLog.structure("{} : deja en cours, doublon ignore", label);
        if (onDone != null) onDone.run();
        return;
    }
    deepluckyblock.util.DebugLog.structure(
            "{} : debut sur {} chunks ({} colonnes)",
            label, zone.chunkCount, zone.columns());
    new ChunkPass(level, label, zone, action, onDone).slice();
}

private static final class ChunkPass {
    final ServerLevel level; final String label;
    final ChunkMajorZone zone; final ChunkAction action; final Runnable onDone;
    final long t0 = System.currentTimeMillis();
    int cursor = 0, deferred = 0;

    ChunkPass(ServerLevel level, String label, ChunkMajorZone zone,
              ChunkAction action, Runnable onDone) {
        this.level = level; this.label = label; this.zone = zone;
        this.action = action; this.onDone = onDone;
    }

    void slice() {
        deepluckyblock.util.ChunkKeeper.keep(level);        // OBLIGATOIRE
        deepluckyblock.util.TerrainChain.heartbeat();        // OBLIGATOIRE
        deepluckyblock.util.DebugLog.setPhase(
                label + " " + cursor + "/" + zone.chunkCount);

        if (!deepluckyblock.util.ChunkKeeper.zoneComplete(level) && deferred < 1200) {
            deferred++;
            TestProcedure.schedule(level, TestProcedure.currentTick(level) + 1, this::slice);
            return;
        }

        long deadline = System.currentTimeMillis() + sliceBudgetMs(level);
        while (cursor < zone.chunkCount) {
            try { action.run(cursor); } catch (Throwable t) {
                LOGGER.warn("[DLB-STRUCTURE] {} : chunk {} en erreur", label, cursor, t);
            }
            cursor++;
            if (System.currentTimeMillis() >= deadline) break;
        }

        if (cursor < zone.chunkCount) {
            TestProcedure.schedule(level, TestProcedure.currentTick(level) + 1, this::slice);
        } else {
            long ms = System.currentTimeMillis() - t0;
            deepluckyblock.util.DebugLog.structure(
                    "{} : termine, {} chunks, {} ms CPU (~{} s ecoulees)",
                    label, zone.chunkCount, ms, String.format("%.2f", ms / 240.0));
            RUNNING_PASSES.remove(label);
            if (onDone != null) onDone.run();
        }
    }
}
```

⚠ Note le log : il affiche **le temps CPU ET le temps écoulé estimé**
(`ms / 240.0` = ms ÷ 12 × 50 ÷ 1000). C'est exactement pour éviter l'erreur de
lecture du §20. **Reprends ce format dans toute nouvelle passe.**

## §61. `dressAndPlant`

```java
/**
 * HABILLAGE + VEGETATION + REPOSE DES PLANTES SAUVEES,
 * en UNE SEULE descente de colonne.
 *
 * Remplace verifyGrassSurface() ET naturalize().
 * Budget : 1 s de temps ecoule, ~6 us/colonne (guide, LIVRE III).
 */
private static void dressAndPlant(ServerLevel level, BlockPos min, BlockPos max,
                                  Runnable onDone) {
    // PERIMETRE : le PLUS GRAND des deux anneaux historiques.
    //   verifyGrassSurface -> terrainRing()
    //   naturalize         -> terrainRing() + NATURALIZE_EXTRA_RING (16)
    // Prendre le plus petit serait une REGRESSION VISIBLE.
    final int innerRing = terrainRing();
    final int outerRing = terrainRing() + NATURALIZE_EXTRA_RING;
    final ChunkMajorZone zone = new ChunkMajorZone(min, max, outerRing);

    deepluckyblock.util.ChunkKeeper.track(level,
            new BlockPos(min.getX() - outerRing, min.getY(), min.getZ() - outerRing),
            new BlockPos(max.getX() + outerRing, max.getY(), max.getZ() + outerRing));

    final long vegSeed = level.getSeed()
            ^ ((long) min.getX() * 912931L) ^ ((long) min.getZ() * 182883L) ^ 0x5EEDL;

    // 0 fastChunks | 1 blendChunks | 2 surfaceSet | 3 fillerSet
    // 4 plants     | 5 skipped     | 6 rescued
    final int[] stats = new int[7];
    final int[] surfCache = new int[256];   // reutilise par chunk, 0 allocation

    startChunkPass(level, "dressAndPlant", zone, (i) -> {
        int cx = zone.chunkX(i), cz = zone.chunkZ(i);
        SurfacePalette pal = paletteAt(level, cx, cz);

        // --- COURT-CIRCUIT niveaux 1 et 2 : quels cotes different ?
        // Comparaison de BLOCK, jamais de BlockState (invariant I4).
        SurfacePalette[] nb = new SurfacePalette[8];
        boolean anyDifferent = false;
        int k = 0;
        for (int dx = -1; dx <= 1; dx++) {
            for (int dz = -1; dz <= 1; dz++) {
                if (dx == 0 && dz == 0) continue;
                SurfacePalette q = paletteAt(level, cx + dx, cz + dz);
                nb[k] = (q.top() == pal.top()) ? null : q;   // null = identique
                if (nb[k] != null) anyDifferent = true;
                k++;
            }
        }
        if (anyDifferent) stats[1]++; else stats[0]++;

        ChunkAccess chunk = level.getChunk(cx, cz);
        BlockPos.MutableBlockPos mut = new BlockPos.MutableBlockPos();  // UNE par chunk
        boolean snowy = isSnowyCell(level, cx, cz);                     // UNE par chunk
        java.util.Arrays.fill(surfCache, -1);

        for (int lz = 0; lz < 16; lz++) {
            for (int lx = 0; lx < 16; lx++) {
                int x = (cx << 4) + lx, z = (cz << 4) + lz;
                if (!zone.contains(x, z)) continue;
                if (isProtected(x, z) || StructureScatterDecor.isInsideDecor(x, z, 1)) {
                    stats[5]++; continue;
                }

                int surfY = surfaceY(level, chunk, mut, x, z);
                if (surfY < 1) { stats[5]++; continue; }
                surfCache[(lz << 4) | lx] = surfY;

                boolean inner = withinRing(min, max, x, z, innerRing);
                Block chosen = pal.top();

                if (inner) {
                    // --- COURT-CIRCUIT niveau 3 + tirage unique pondere
                    if (anyDifferent) chosen = pickGround(pal, nb, x, z, lx, lz);

                    BlockState cur = readBlock(level, chunk, mut, x, surfY, z);
                    // Regle 6 : ne rien ecrire si c'est deja correct.
                    if (cur.getBlock() != chosen
                            && isNaturalTerrain(cur) && cur.blocksMotion()) {
                        level.setBlock(mut.set(x, surfY, z),
                                chosen.defaultBlockState(), FAST_FLAG);
                        stats[2]++;
                    }

                    Block filler = fillerFor(chosen);
                    if (filler != null) {
                        for (int d = 1; d <= SUBSOIL_DEPTH; d++) {
                            BlockState s = readBlock(level, chunk, mut, x, surfY - d, z);
                            if (!isNaturalTerrain(s) || !s.blocksMotion()) break;
                            if (s.getBlock() == filler) continue;       // deja correct
                            level.setBlock(mut.set(x, surfY - d, z),
                                    filler.defaultBlockState(), FAST_FLAG);
                            stats[3]++;
                        }
                    }

                    if (snowy) applySnowLayer(level, mut, x, surfY, z);
                }

                // --- VEGETATION, sur le bloc de surface FINAL
                if (plantOn(level, mut, x, surfY, z, chosen, vegSeed)) stats[4]++;
            }
        }

        // --- REPOSE DES PLANTES SAUVEES (LIVRE VII), surfY deja en cache
        stats[6] += replantRescued(level, chunk, mut, cx, cz, surfCache);

    }, () -> {
        deepluckyblock.util.DebugLog.structure(
                "dressAndPlant : {} chunks rapides / {} melanges, {} surfaces, "
                        + "{} sous-sols, {} plantes, {} sauvees reposees, "
                        + "{} colonnes sautees, {} replis de palette",
                stats[0], stats[1], stats[2], stats[3], stats[4], stats[6],
                stats[5], PALETTE_FALLBACKS);
        PALETTE.clear();
        RESCUE.clear();
        PALETTE_FALLBACKS = 0;
        rescueTotal = 0;
        if (onDone != null) onDone.run();
    });
}
```

## §62. Les méthodes auxiliaires

```java
private static final int SUBSOIL_DEPTH = 3;

/** Y de la surface, chunk deja resolu. Heightmap = borne haute uniquement. */
private static int surfaceY(ServerLevel level, ChunkAccess chunk,
                            BlockPos.MutableBlockPos mut, int x, int z) {
    int y = deepluckyblock.util.SafeSurface.height(
            level, Heightmap.Types.MOTION_BLOCKING_NO_LEAVES, x, z) - 1;
    int floor = level.getMinBuildHeight() + 8;
    while (y > floor) {
        BlockState s = readBlock(level, chunk, mut, x, y, z);
        if (s.blocksMotion() && !isLog(s) && !isLeaf(s)) return y;
        y--;
    }
    return -1;
}

/** La colonne est-elle dans l'anneau interieur (zone d'habillage) ? */
private static boolean withinRing(BlockPos min, BlockPos max, int x, int z, int ring) {
    return x >= min.getX() - ring && x <= max.getX() + ring
        && z >= min.getZ() - ring && z <= max.getZ() + ring;
}

/**
 * Biome enneige, resolu UNE FOIS PAR CHUNK.
 * Remplace isSnowy() qui comparait des CHAINES par colonne (regle 5).
 */
private static final Map<Long, Boolean> SNOWY_CELL = new HashMap<>();

private static boolean isSnowyCell(ServerLevel level, int cx, int cz) {
    long key = net.minecraft.world.level.ChunkPos.asLong(cx, cz);
    Boolean v = SNOWY_CELL.get(key);
    if (v != null) return v;
    boolean snowy = isSnowy(level, new BlockPos((cx << 4) + 8, 80, (cz << 4) + 8));
    SNOWY_CELL.put(key, snowy);
    return snowy;
}

/** Couche de neige au-dessus de la surface, si le biome est enneige. */
private static void applySnowLayer(ServerLevel level, BlockPos.MutableBlockPos mut,
                                   int x, int surfY, int z) {
    mut.set(x, surfY + 1, z);
    if (level.getBlockState(mut).isAir())
        level.setBlock(mut, Blocks.SNOW.defaultBlockState(), FAST_FLAG);   // pas le flag 3
}
```

⚠ `isSnowyCell` est indexé **par chunk**, pas par cellule 4×4. C'est un
compromis assumé : la neige est une propriété très locale visuellement, mais un
chunk entièrement dans un biome enneigé est le cas courant. **Si un artefact
apparaît aux frontières de biomes enneigés, passer à une clé 4×4.**

## §79. Méthode de mesure honnête

- **Marqueur de début :** `[DLBTEST] <nom> demandee a X, Y, Z`.
- **Marqueur de fin :** le dernier
  `[DLB-STRUCTURE] [<durée> s] decorate TERMINE`, confirmé par
  `[DLB-PERF] TACHE COMPLETE en <durée> s`.
- Exemple dragon 27/09 : 16:27:08 → 16:29:08 = **107,5 s**.

⚠ **PIÈGE :** la ligne `✓ dragon en 103995ms` ne couvre que **jusqu'au
collage**. 🔒 **Ne jamais rapporter ce chiffre flatteur.**

- Isoler le chargement NBT de fond : ce n'est pas du calcul.
- **Anomalie = coût unitaire**, pas temps absolu. `clearSurfaceDecor` fait
  40 176 colonnes en 11 836 ms = **0,29 ms/colonne**, contre les mêmes colonnes
  en 838 ms pour `verifyGrassSurface` : **14× plus cher**. C'est le signal.
- Surveiller `colonne(s) lente(s) (> 50 ms, pire 180 ms)` et `Can't keep up!`.
- **Attendre ≠ calculer** : `preload` est une attente de génération de chunks.
- Une **disproportion** (46 539 colonnes pour 239 715 blocs d'eau) est un **bug
  de périmètre**, pas un besoin d'optimisation.

**Protocole :** même graine, mêmes coordonnées, même build CI (2 CPU / 2 Go),
**au moins 2 runs**, comparer **poste par poste** et pas seulement le total.
Consigner total + top 3 postes + µs/colonne dans `JOURNAL_AUTONOME.md`.

## §80. Protocole de mesure statistique

Leçon tirée de l'erreur du §44.1. À appliquer à tout test d'algorithme :

1. 🔒 **Taille d'échantillon minimale : 512**, jamais 16. Pour une proportion
   attendue *p*, l'écart-type est `sqrt(p(1−p)/n)` — à n = 16 et p = 0,3, cela
   fait **±11,5 points**, plus que l'effet cherché.
2. **Mesurer sur l'axe où l'effet varie**, jamais perpendiculairement. C'est ce
   qui a démasqué la quantification de Bayer.
3. **Au moins un critère de structure**, pas seulement de moyenne : ici, le
   nombre de motifs distincts. Une moyenne parfaite peut cacher une répétition
   parfaitement visible.
4. **Tester les variantes intermédiaires.** La série des cinq gigues a montré
   une convergence monotone — information qu'aucun test binaire n'aurait donnée.
5. **Consigner le tableau complet**, y compris les variantes perdantes, pour
   que personne ne rouvre le test.

| **Plantes absentes sans erreur** | `canSurvive` qui teste la lumière (§16) | chercher un mod de lumière |
| **Tournesols en double** | moitié `UPPER` comptée au scan | §54, test `HALF` |
| Plante double qui **disparaît à la pose** | flag `3` au lieu de `FAST_FLAG` | §52.3 |
| **Erreur de compilation** sur un nom de tag | extrait copié depuis de la doc 1.21.5 | §17 |
| **Couvercle d'herbe sur de l'eau** | habillage avant drainage | invariant I2 |
| **Gel de 15-27 s** en pleine passe | `getChunk` hors zone épinglée | §11.3 ; vérifier `ChunkKeeper.track` |
| **`Can't keep up!`** | tranche trop longue, ou `SLICE_BUDGET_MS` relevé | comparer le MSPT avant/après |
| Colonnes **non traitées** en fin de passe | chunks jamais chargés (`missed`, `MAX_MISS_RETRIES`) | le log l'annonce honnêtement |
| **Pierre visible en pente** | sous-sol non posé (`fillerFor` a renvoyé `null`) | ajouter le sol à la table §31 |
| **Sable qui tombe** après la pose | flag `3` au lieu de `FAST_FLAG` | règle 7 |
| **Mémoire qui grimpe** sur everest | `RESCUE` non vidé en fin de chaîne | contrôle n°20 |
| **Aucune plante moddée sauvée** | le mod n'hérite pas de `BushBlock` | journaliser les blocs rejetés par `isGroundPlant` |
| **Taux de repose de 100 %** | ⚠ `canSurvive` n'est pas appelé | §58 |
| **Inondation de la carte** | `fixWaterNearStructure` remplit des colonnes sèches | §10 |

## §84. Journal des décisions

Chaque décision avec ce qui a été **écarté** et **pourquoi** — pour qu'on ne
repropose pas une option déjà éliminée.

**D1 — Échantillonner le terrain plutôt qu'interroger le biome.**
*Rejeté :* lire `topBlock` du biome. En 1.21.1 la surface vient des
`SurfaceRules` du datapack ; il n'existe pas d'API simple, et les biomes moddés
sont imprévisibles. L'échantillonnage est agnostique par construction.

**D2 — Tramage plutôt que dégradé.**
*Rejeté :* interpoler. Un bloc est discret, il n'y a rien à interpoler. Le
tramage est l'équivalent discret, et c'est ce que fait Pufferfish's Biome
Dither.

**D3 — Hash de position plutôt que RNG.**
*Rejeté :* `level.getRandom()`. Les passes sont rejouées ; un RNG ferait
changer une colonne d'un passage à l'autre.

**D4 — Un tirage unique pondéré plutôt que des règles successives.**
*Rejeté :* appliquer la règle ouest puis la règle nord. Démonstration chiffrée
en §36 : le coin penche.

**D5 — Fusionner plutôt qu'ajouter une passe.**
*Rejeté :* une passe `dressSurface` autonome. Impossible arithmétiquement sous
1 s (§22). La décision la plus structurante.

**D6 — `canSurvive` plutôt qu'une table sol↔plante.**
*Rejeté :* la table en dur de la conception initiale. Elle ne couvrait ni les
mods, ni les règles d'adjacence du cactus.

**D7 — Table de densité conservée malgré `canSurvive`.**
`canSurvive` répond « est-ce possible », pas « est-ce souhaitable ». La densité
et le choix d'espèce restent des décisions de goût.

**D8 — Anneau de végétation conservé à `terrainRing() + 16`.**
*Rejeté :* aligner la végétation sur l'anneau d'habillage, plus petit. Ce serait
une régression visible en jeu, donc soumise à accord.

**D9 — Ne pas supprimer les anciennes méthodes.**
Consigne permanente : on les laisse non appelées, commentées.

**D10 — `Block` et non `BlockState` pour comparer les palettes.**
*Rejeté :* comparer les états. `snowy=true` créerait de faux mélanges.

**D11 — Le hash est conservé, le tramage ordonné est rejeté.**
*Rejeté :* Bayer 4×4, Bayer 8×8, et cinq variantes hybrides. Mesuré en §44 :
quantification sur l'axe de la bande (rangée externe toujours vide) et
périodicité visible (4 motifs sur 256).

**D12 — La distance au bord est perturbée par un bruit basse fréquence.**
*Rejeté :* laisser la bande rectiligne. Sans perturbation, l'œil reconstruit le
carré 16×16 malgré le tramage (§42).

**D13 — Inventaire par chunk plutôt que positions sauvegardées.**
*Rejeté :* mémoriser la position de chaque plante. Le terrain a changé : la
position d'origine n'est plus valide, et le coût mémoire serait celui de
`SavedTree`.

**D14 — Seules les plantes de sol sont sauvées.**
*Rejeté :* sauver aussi les lianes, le spore blossom, le kelp. Trois modèles de
support différents pour un gain marginal ; `sweepFloatingDecor` les retire déjà
proprement.

**D15 — `BushBlock` comme filet pour les mods.**
*Rejeté :* une liste en dur d'espèces. En 1.21.1 la quasi-totalité des plantes
de sol en hérite, y compris celles des mods.

## §85. FAQ

**« Par où je commence ? »** §3, puis commit 1 du §68.

**« Je peux compiler ? »** Non, pas localement (§77). Uniquement la CI.
8 lancements autorisés par message.

**« Je dois demander confirmation avant d'implémenter ? »** Non (§99), sauf
changement d'architecture ou changement visible par le joueur. Passer la bande
de 5 à 8 blocs **est** visible : à soumettre. La fusion des deux passes ne l'est
pas, si le rendu est équivalent.

**« Pourquoi ne pas juste optimiser `verifyGrassSurface` ? »** Parce qu'elle
n'est pas seulement lente, elle est **fausse** (§8.1) : elle peint du gazon sur
tout sauf trois blocs codés en dur.

**« Est-ce que ça fera passer le dragon sous 30 s ? »** Non. `fixLiquids` +
`preload` = 61 % (§25). Ne confonds pas les deux chantiers.

**« Les chiffres de ce document sont-ils mesurés ? »** Ceux marqués **MESURÉ**
oui : les temps viennent du log du dragon du 27/09, les statistiques de tramage
des scripts `docs/images/*.py`. Ceux marqués **CALCULÉ** sont dérivés des
constantes du code. **Aucune ligne de code n'a été compilée ni exécutée en
jeu.**

**« Que faire si je dépasse 1 s ? »** §24. Jamais relâcher le seuil.

**« Puis-je supprimer les vieux fichiers ? »** Non sans accord (§99).

**« Et si la palette se trompe ? »** Le compteur de replis et le compteur de
chunks mélangés le disent (§38.3). Un désert avec beaucoup de chunks mélangés =
palette fausse.

**« Pourquoi 16 témoins et pas 4 ou 64 ? »** 16 donne un seuil de confiance à 8
avec une marge raisonnable, pour un coût de 16 descentes par chunk, soit
0,06 descente par colonne. **SUPPOSÉ** : non optimisé, candidat à mesure.

**« Le tramage ordonné, vraiment pas ? »** Vraiment pas. §44, avec les chiffres.
Ne rouvre pas ce test.

**« Pourquoi le cactus en dernier ? »** §52.2. Il casse si un bloc solide
apparaît à côté **après** sa pose.

**« Comment prévisualiser un changement de constante ? »** Les scripts Python
(§44.5). Pas besoin de JDK.

## §86. Les six invariants, rappelés

🔒 **I1.** La palette s'échantillonne **avant toute édition**.
🔒 **I2.** Le drainage passe **avant** l'habillage.
🔒 **I3.** Le tramage est **déterministe** (hash de position).
🔒 **I4.** On compare des **`Block`**, jamais des `BlockState`.
🔒 **I5.** On **n'ajoute jamais une passe** : on fusionne.
🔒 **I6.** Toute lecture reste **dans la zone épinglée** par `ChunkKeeper`.

## §88. Les tests A/B restant à mener

**A/B n°1 — largeur de bande : 5 contre 8 blocs.**
Justification : vanilla mélange sur 7, Better Biome Blend sur 15 (§35).
Critère : la frontière est-elle encore lisible en jeu, et de combien augmente le
coût du chemin mélangé ?
⚠ Changement **visible par le joueur** : à soumettre à l'utilisateur.
Prévisualisable sans compiler : modifier `BLEND_BAND` dans
`docs/images/render_transitions.py`.

**A/B n°2 — type de tramage. TRANCHÉ (§44), ne pas rouvrir.**

**A/B n°3 — table de végétation contre features du biome (§48).**
Critère : densité obtenue et fidélité au biome, contre prévisibilité.
Mesurer la densité réelle, ne pas supposer.

**A/B n°4 — rayon de palette 1 chunk contre 2 chunks (§43.2).**
Permettrait un serpentement libre. Critère : coût supplémentaire réel, que le
court-circuit devrait absorber. **Non démontré.**

**A/B n°5 — nombre de témoins de palette : 4, 16, 64.**
Critère : taux de replis contre coût. 16 est un choix **SUPPOSÉ**, non optimisé.

## §89. Le carnet de commandes général

Hors habillage, par priorité :

1. **Réparation d'eau** : ne jamais remplir une colonne sèche, ni élever un
   niveau au-dessus du plan d'eau connecté. Le facteur ×4 sur le rayon a inondé
   la carte — 🔒 **garder la portée large, interdire le remplissage à sec**.
2. **Ancrage sûr** : repli sur la médiane mesurée du sol, en **préservant les
   décalages de modèle** (dragon −34, citadelle −35, observatoire −5,
   enfoncement du lac 10).
3. **Everest** et les autres chemins « sans terraformation » : les **exclure**
   des passes lourdes de terrain.
4. **Dragon sous 30 s** : cibles `fixLiquids` 34,3 s et `preload` 30,6 s.
5. **Sélection de site** : ne jamais retomber sur un candidat brut non mesuré.
6. **Affaissement de 2 à 4 blocs** près de la structure.
7. **Publication d'un paquet source** sur GitHub avec lien HTTPS cliquable
   (demandé, non fait).

SLA global : **six structures ≤ 30 s**, **lac 10-120 s**.

### `scanTrees` — ligne 1273

## §107. Bloc 2 — le bruit de position

**Pourquoi pas `Random` ?** Trois raisons.

1. **Reproductibilité.** Deux exécutions sur la même graine doivent donner le
   même paysage, sinon l'A/B du §80 ne mesure que du bruit.
2. **Indépendance de l'ordre.** Avec un `Random`, le résultat d'une colonne
   dépend du nombre de colonnes traitées avant elle. Change la taille du lot,
   change le paysage. Avec un hash de position, **chaque colonne est
   indépendante** — on peut découper la passe en tranches librement.
3. **Coût.** `posNoise` c'est 6 opérations entières. `Random.nextFloat()` c'est
   un appel virtuel plus une multiplication 64 bits plus un masque.

**Pourquoi ces constantes ?** `0x27d4eb2d`, `0x85ebca6b`, `0x165667b1` sont des
multiplicateurs xorshift éprouvés (respectivement de la famille Wang,
de MurmurHash3 et de xxHash). Vérifié cette session : sur 6 400 chunks, moyenne
0,4985 et écart-type 0,2889, à comparer à la théorie d'une loi uniforme
(0,5 et 0,2887). **Aucune périodicité détectée.**

```java
/**
 * Bruit blanc deterministe en [0,1[ a partir d'une position et d'un sel.
 *
 * Chaque (x, z, salt) donne toujours la meme valeur, quelle que soit
 * l'ordre de parcours. C'est ce qui rend la passe decoupable en tranches.
 */
private static float posNoise(int x, int z, int salt) {
    int h = x * 0x27d4eb2d ^ z * 0x85ebca6b ^ salt * 0x165667b1;
    h ^= h >>> 15;
    h *= 0x2545f491;
    h ^= h >>> 13;
    return (h & 0x00ffffff) / (float) 0x01000000;
}

/**
 * Courbe en S de Perlin : derivee nulle aux deux bouts.
 * Sans elle, le bruit de valeur montre les aretes de la grille.
 */
private static float smoothstep(float t) {
    return t * t * (3f - 2f * t);
}

/**
 * Bruit de valeur : bruit blanc sur une grille de pas `cell`, interpole.
 * Contrairement a posNoise, deux points voisins donnent des valeurs
 * proches. C'est ce qu'il faut pour deformer une frontiere de facon
 * continue plutot que de la dechiqueter.
 */
private static float valueNoise(int x, int z, int cell, int salt) {
    int gx = Math.floorDiv(x, cell);
    int gz = Math.floorDiv(z, cell);
    float fx = smoothstep(Math.floorMod(x, cell) / (float) cell);
    float fz = smoothstep(Math.floorMod(z, cell) / (float) cell);

    float n00 = posNoise(gx,     gz,     salt);
    float n10 = posNoise(gx + 1, gz,     salt);
    float n01 = posNoise(gx,     gz + 1, salt);
    float n11 = posNoise(gx + 1, gz + 1, salt);

    float a = n00 * (1f - fx) + n10 * fx;
    float b = n01 * (1f - fx) + n11 * fx;
    return a * (1f - fz) + b * fz;
}

/**
 * Distance a la frontiere, deformee.
 *
 * Sans deformation, la bande de melange est un rectangle parfait : on voit
 * une bande droite de 5 blocs le long du bord du chunk, et l'oeil la repere
 * immediatement. En bruitant la distance, la frontiere ondule de +/- 4 blocs
 * avec une longueur d'onde de 12 blocs : on percoit une transition naturelle.
 *
 * @param d    distance reelle au bord, en blocs (1 = colle au bord)
 * @param salt sel propre au cote considere, pour que les 4 cotes
 *             n'ondulent pas en phase
 */
private static float effectiveDistance(int d, int x, int z, int salt) {
    float w = (valueNoise(x, z, WARP_CELL, salt) - 0.5f) * 2f * WARP_AMP;
    return d - w;
}

/**
 * Probabilite d'emprunter le bloc du voisin, a une distance donnee du bord.
 *
 * d=1 -> 50 %, d=2 -> 40 %, d=3 -> 30 %, d=4 -> 20 %, d=5 -> 10 %, d>5 -> 0 %.
 *
 * Le plafond a 50 % est essentiel : au contact exact, les deux sols sont
 * equiprobables, ce qui donne une frontiere symetrique. Au-dela de 50 %,
 * le voisin gagnerait et la frontiere se deplacerait.
 */
private static float edgeP(float distance) {
    if (distance <= 0f) return 0.5f;
    if (distance > BLEND_BAND) return 0f;
    return (BLEND_BAND + 1f - distance) * 0.5f / BLEND_BAND;
}
```

## §108. Bloc 3 — l'échantillonnage de la palette

**L'idée.** Avant de toucher au terrain, on regarde ce que la nature avait mis
là. Pour chaque chunk de la zone, on sonde **16 colonnes témoins** (une grille
4×4 aux coordonnées 2, 6, 10, 14) et on compte les blocs de surface. Le plus
fréquent devient la palette du chunk.

**Pourquoi 16 et pas 256 ?** Parce qu'un chunk est presque toujours homogène.
16 échantillons donnent un écart-type de ±12 points sur une proportion, ce qui
est largement suffisant pour trancher entre « sable » et « herbe » (écart de
80 points), et 16× moins cher que 256.

**Pourquoi des colonnes témoins et pas le biome ?** Parce que le biome ment.
Un `plains` peut contenir une plage de sable, un `desert` peut contenir une
oasis d'herbe. On veut **ce qui est réellement posé**, pas ce que la table de
biomes prétend.

🔒 **Cet échantillonnage doit se faire AVANT le terrassement**, sinon on
échantillonne le dégât qu'on essaie de réparer. C'est pour cela que le commit 4
place l'appel dans `prepZone`, pas dans `decorateChain`.

```java
/**
 * Un bloc peut-il servir de bloc de surface de reference ?
 *
 * On accepte les sols naturels connus. On refuse tout ce qui est pose
 * PAR-DESSUS le sol (neige, decor) et tout ce qui est artificiel.
 */
private static boolean isGroundCandidate(Block b) {
    return b == Blocks.GRASS_BLOCK
        || b == Blocks.DIRT
        || b == Blocks.COARSE_DIRT
        || b == Blocks.ROOTED_DIRT
        || b == Blocks.PODZOL
        || b == Blocks.MYCELIUM
        || b == Blocks.SAND
        || b == Blocks.RED_SAND
        || b == Blocks.GRAVEL
        || b == Blocks.STONE
        || b == Blocks.SNOW_BLOCK
        || b == Blocks.TERRACOTTA
        || b == Blocks.WHITE_TERRACOTTA
        || b == Blocks.ORANGE_TERRACOTTA
        || b == Blocks.YELLOW_TERRACOTTA
        || b == Blocks.BROWN_TERRACOTTA
        || b == Blocks.RED_TERRACOTTA
        || b == Blocks.LIGHT_GRAY_TERRACOTTA
        || b == Blocks.MUD
        || b == Blocks.MOSS_BLOCK
        || b == Blocks.CLAY
        || b == Blocks.PACKED_ICE
        || b == Blocks.SOUL_SAND;
}

/**
 * Blocs a traverser pour trouver le vrai sol : ils sont POSES dessus.
 *
 * Sans cela, un chunk enneige renvoie une palette "snow" et on reecrit
 * de la neige a la place de l'herbe : le printemps n'arrive jamais.
 */
private static boolean isSkippableCover(Block b) {
    return b == Blocks.SNOW
        || b == Blocks.POWDER_SNOW
        || b == Blocks.MOSS_CARPET
        || b instanceof BushBlock
        || b == Blocks.WATER
        || b == Blocks.ICE
        || b == Blocks.FROSTED_ICE;
}

/**
 * Bloc de sous-sol correspondant a un bloc de surface.
 *
 * Sans cela, on pose de l'herbe sur du sable en plein desert : la colonne
 * a l'air correcte vue du dessus, mais la moindre falaise revele la triche.
 */
private static Block fillerFor(Block top) {
    if (top == Blocks.GRASS_BLOCK)  return Blocks.DIRT;
    if (top == Blocks.PODZOL)       return Blocks.DIRT;
    if (top == Blocks.MYCELIUM)     return Blocks.DIRT;
    if (top == Blocks.MOSS_BLOCK)   return Blocks.DIRT;
    if (top == Blocks.SAND)         return Blocks.SAND;
    if (top == Blocks.RED_SAND)     return Blocks.RED_SAND;
    if (top == Blocks.GRAVEL)       return Blocks.GRAVEL;
    if (top == Blocks.SNOW_BLOCK)   return Blocks.SNOW_BLOCK;
    if (top == Blocks.MUD)          return Blocks.MUD;
    if (top == Blocks.CLAY)         return Blocks.CLAY;
    if (top == Blocks.STONE)        return Blocks.STONE;
    if (top == Blocks.SOUL_SAND)    return Blocks.SOUL_SAND;
    if (top.getDescriptionId().contains("terracotta")) return top;
    return Blocks.DIRT;
}

/**
 * Echantillonne la palette d'un chunk deja charge.
 *
 * Cout : 16 colonnes, chacune lisant au plus 6 blocs (la couverture fait
 * rarement plus de 2 blocs d'epaisseur). Soit ~96 lectures par chunk,
 * contre 256 colonnes x 1 lecture pour la passe principale : environ
 * 37 % de surcout sur la lecture, une seule fois, hors boucle chaude.
 */
private static SurfacePalette samplePalette(ServerLevel level, LevelChunk chunk) {
    Map<Block, Integer> tally = new HashMap<>();
    BlockPos.MutableBlockPos mut = new BlockPos.MutableBlockPos();
    int baseX = chunk.getPos().getMinBlockX();
    int baseZ = chunk.getPos().getMinBlockZ();
    int samples = 0;

    for (int dx : WITNESS) {
        for (int dz : WITNESS) {
            int wx = baseX + dx;
            int wz = baseZ + dz;
            int y = chunk.getHeight(Heightmap.Types.WORLD_SURFACE_WG, dx, dz);

            // On descend a travers la couverture pour trouver le vrai sol.
            for (int step = 0; step < 6 && y > level.getMinBuildHeight(); step++) {
                mut.set(wx, y, wz);
                Block b = chunk.getBlockState(mut).getBlock();
                if (isGroundCandidate(b)) {
                    tally.merge(b, 1, Integer::sum);
                    samples++;
                    break;
                }
                if (!isSkippableCover(b) && !b.defaultBlockState().isAir()) {
                    break;   // bloc artificiel ou inconnu : on abandonne cette colonne
                }
                y--;
            }
        }
    }

    if (samples == 0) {
        paletteFallbacks++;
        return new SurfacePalette(Blocks.GRASS_BLOCK, Blocks.DIRT, 0, false);
    }

    Block top = tally.entrySet().stream()
            .max(Comparator.comparingInt(Map.Entry::getValue))
            .map(Map.Entry::getKey)
            .orElse(Blocks.GRASS_BLOCK);

    return new SurfacePalette(top, fillerFor(top), samples, samples >= PALETTE_MIN_SAMPLES);
}

/**
 * Palette d'un chunk, depuis le cache. Ne charge JAMAIS un chunk.
 *
 * Si le chunk n'a pas ete echantillonne (hors zone, ou pas encore charge),
 * on renvoie null et l'appelant retombe sur la palette locale. C'est le
 * comportement voulu : mieux vaut pas de melange qu'un chargement
 * synchrone au milieu d'une boucle de colonnes.
 */
private static SurfacePalette paletteAt(int chunkX, int chunkZ) {
    return PALETTE.get(ChunkPos.asLong(chunkX, chunkZ));
}
```

## §109. Bloc 4 — le tirage du bloc de sol

**Le piège du coin, expliqué une dernière fois.** La version naïve applique
deux règles successives :

```java
// ❌ FAUX
if (posNoise(x, z, SALT_A) < pOuest) bloc = ouest;
if (posNoise(x, z, SALT_B) < pNord)  bloc = nord;
```

Dans un coin, les deux conditions valent 50 %. La seconde écrase la première :
le nord gagne 50 % du temps, l'ouest 25 %, le local 25 %. **La frontière se
déplace en diagonale dans tous les coins de la zone**, ce qui produit une
grille visible à l'échelle du chunk.

**La solution :** un seul tirage, et on découpe l'intervalle [0,1[ en segments
proportionnels. C'est exactement une roulette pondérée.

```java
// Indices nommes du tableau de voisins. NE JAMAIS ecrire ces indices
// en litteral : nb[7] a deja ete pris pour l'EST alors que c'est le
// SUD-EST, et le bug a survecu a deux relectures.
private static final int NB_NW = 0;
private static final int NB_N  = 1;
private static final int NB_NE = 2;
private static final int NB_W  = 3;
private static final int NB_E  = 4;
private static final int NB_SW = 5;
private static final int NB_S  = 6;
private static final int NB_SE = 7;

/**
 * Choisit le bloc de surface d'une colonne, en melangeant avec les voisins
 * quand on est pres d'une frontiere.
 *
 * OPTIMISATION MAJEURE (regle de conception imposee) : si tous les voisins
 * pertinents portent la meme palette que la colonne locale, on sort
 * immediatement. Sable a cote de sable ne demande AUCUN calcul de melange.
 * Sur une zone typique, plus de 80 % des chunks sont dans ce cas : le
 * court-circuit economise la quasi-totalite du cout du degrade.
 *
 * @param nb tableau de 8 palettes voisines, indices NB_*, null si absent
 */
private static Block pickGround(int x, int z, SurfacePalette local, SurfacePalette[] nb) {

    // ---- COURT-CIRCUIT : aucun voisin different -> aucun melange ------
    boolean anyDifferent = false;
    for (int i = 0; i < 8; i++) {
        if (nb[i] != null && nb[i].top() != local.top()) { anyDifferent = true; break; }
    }
    if (!anyDifferent) return local.top();

    // ---- Distances aux quatre bords, deformees -----------------------
    int lx = x & 15;
    int lz = z & 15;
    float dW = effectiveDistance(lx + 1,      x, z, SALT_WARP);
    float dE = effectiveDistance(16 - lx,     x, z, SALT_WARP + 1);
    float dN = effectiveDistance(lz + 1,      x, z, SALT_WARP + 2);
    float dS = effectiveDistance(16 - lz,     x, z, SALT_WARP + 3);

    // ---- Accumulation des poids --------------------------------------
    // On ne compte un voisin que s'il DIFFERE : un voisin identique
    // n'a rien a apporter et son poids serait du bruit pur.
    float[] w = new float[8];
    float total = 0f;

    total += (w[NB_W] = weightOf(nb[NB_W], local, edgeP(dW)));
    total += (w[NB_E] = weightOf(nb[NB_E], local, edgeP(dE)));
    total += (w[NB_N] = weightOf(nb[NB_N], local, edgeP(dN)));
    total += (w[NB_S] = weightOf(nb[NB_S], local, edgeP(dS)));

    // Les diagonales ne comptent que dans le coin, avec le MINIMUM des
    // deux distances : sinon le coin recevrait trois contributions et
    // le local serait minoritaire chez lui.
    total += (w[NB_NW] = weightOf(nb[NB_NW], local, edgeP(Math.max(dW, dN)) * 0.5f));
    total += (w[NB_NE] = weightOf(nb[NB_NE], local, edgeP(Math.max(dE, dN)) * 0.5f));
    total += (w[NB_SW] = weightOf(nb[NB_SW], local, edgeP(Math.max(dW, dS)) * 0.5f));
    total += (w[NB_SE] = weightOf(nb[NB_SE], local, edgeP(Math.max(dE, dS)) * 0.5f));

    if (total <= 0f) return local.top();

    // Plafond : le local garde toujours au moins 50 % chez lui, sinon
    // la frontiere se deplace au lieu de se brouiller.
    if (total > 0.5f) {
        float k = 0.5f / total;
        for (int i = 0; i < 8; i++) w[i] *= k;
        total = 0.5f;
    }

    // ---- Roulette : UN SEUL tirage -----------------------------------
    float r = posNoise(x, z, SALT_GROUND);
    float acc = 0f;
    for (int i = 0; i < 8; i++) {
        acc += w[i];
        if (r < acc) { blendedColumns++; return nb[i].top(); }
    }
    return local.top();
}

/** Poids d'un voisin : nul s'il est absent, peu fiable, ou identique. */
private static float weightOf(SurfacePalette n, SurfacePalette local, float p) {
    if (n == null || !n.confident() || n.top() == local.top()) return 0f;
    return Math.max(0f, p);
}
```

**Recommandation.** Le tableau `float[8] w` est alloué à chaque colonne. Sur
40 000 colonnes, c'est 40 000 petits tableaux — l'échappement est local, donc le
JIT peut les éliminer (scalar replacement), **mais ce n'est pas garanti**. Si le
profil montre de la pression GC ici, remplace par huit variables locales
`wW, wE, wN, wS, wNW, wNE, wSW, wSE` : plus laid, mais sûr. Ne fais ce
changement **qu'après avoir mesuré**.

## §110. Bloc 5 — la zone de chunks et la passe découpée

**Le problème à résoudre.** Le serveur doit répondre en 50 ms par tick. Une
passe qui traite 40 000 colonnes d'un coup gèle le serveur pendant plusieurs
secondes, et le chien de garde tue le monde. Toutes les passes lourdes de ce
mod sont donc **découpées en tranches** : on travaille jusqu'à un budget de
temps, puis on rend la main, et on reprend au tick suivant.

**Pourquoi une passe par CHUNK et non par colonne ?** Trois gains.

1. On résout le chunk **une fois** au lieu de 256 fois. Rappel de la mesure :
   `readBlock` sur un chunk résolu coûte 5 unités, `level.getBlockState` en
   coûte 63. **Facteur 12,6.**
2. On échantillonne la palette et on lit les 8 voisins **une fois par chunk**,
   pas par colonne.
3. Le sauvetage des plantes raisonne naturellement par chunk (inventaire par
   chunk, §54).

```java
/**
 * Zone de travail exprimee en chunks, pas en blocs.
 *
 * Construite une fois au debut de la passe. Elle connait la liste ordonnee
 * des chunks a traiter et sait dire si un bloc est dans l'anneau.
 */
private static final class ChunkMajorZone {
    final int minCX, minCZ, maxCX, maxCZ;
    final int centerX, centerZ, ring;
    final List<Long> order = new ArrayList<>();

    ChunkMajorZone(int centerX, int centerZ, int ring) {
        this.centerX = centerX;
        this.centerZ = centerZ;
        this.ring    = ring;
        this.minCX = (centerX - ring) >> 4;
        this.maxCX = (centerX + ring) >> 4;
        this.minCZ = (centerZ - ring) >> 4;
        this.maxCZ = (centerZ + ring) >> 4;

        // Ordre en spirale depuis le centre : les chunks les plus visibles
        // sont habilles en premier. Si la passe est interrompue, le degat
        // visuel est en peripherie, pas sous le nez du joueur.
        int ccx = centerX >> 4, ccz = centerZ >> 4;
        List<long[]> tmp = new ArrayList<>();
        for (int cx = minCX; cx <= maxCX; cx++) {
            for (int cz = minCZ; cz <= maxCZ; cz++) {
                long d2 = (long) (cx - ccx) * (cx - ccx) + (long) (cz - ccz) * (cz - ccz);
                tmp.add(new long[] { d2, ChunkPos.asLong(cx, cz) });
            }
        }
        tmp.sort(Comparator.comparingLong(a -> a[0]));
        for (long[] e : tmp) order.add(e[1]);
    }

    int chunkCount() { return order.size(); }

    /** Le bloc (x,z) est-il dans l'anneau circulaire, et non dans l'emprise ? */
    boolean contains(int x, int z) {
        int dx = x - centerX, dz = z - centerZ;
        return dx * dx + dz * dz <= ring * ring;
    }
}

/** Ce qu'on fait d'un chunk. Permet de reutiliser ChunkPass ailleurs. */
@FunctionalInterface
private interface ChunkAction {
    void run(ServerLevel level, LevelChunk chunk, ChunkMajorZone zone);
}

/**
 * Passe decoupee : traite des chunks jusqu'a epuisement du budget de temps,
 * puis se replanifie au tick suivant.
 *
 * Le budget est volontairement bas (12 ms sur les 50 ms d'un tick, soit
 * 24 % de taux d'occupation). C'est le meme reglage que verifyGrassSurface,
 * qui consommait 838 ms de CPU pour environ 3,5 s de temps ecoule : le
 * facteur 4,2 entre CPU et temps ecoule vient de la.
 */
private static final class ChunkPass {
    private final ServerLevel level;
    private final ChunkMajorZone zone;
    private final ChunkAction action;
    private final Runnable onDone;
    private final String name;
    private int cursor = 0;
    private long cpuNanos = 0L;
    private final long startedAt = System.currentTimeMillis();

    ChunkPass(ServerLevel level, ChunkMajorZone zone, String name,
              ChunkAction action, Runnable onDone) {
        this.level = level; this.zone = zone; this.name = name;
        this.action = action; this.onDone = onDone;
    }

    void tick() {
        long t0 = System.nanoTime();
        long budget = 12L * 1_000_000L;

        while (cursor < zone.order.size() && System.nanoTime() - t0 < budget) {
            long key = zone.order.get(cursor++);
            int cx = ChunkPos.getX(key), cz = ChunkPos.getZ(key);

            // hasChunk : on ne provoque JAMAIS un chargement synchrone
            // au milieu d'une tranche. Un chunk absent est simplement saute ;
            // le preload l'aura amene avant qu'on revienne dessus.
            if (!level.hasChunk(cx, cz)) continue;
            LevelChunk chunk = level.getChunk(cx, cz);
            action.run(level, chunk, zone);
        }

        cpuNanos += System.nanoTime() - t0;

        if (cursor >= zone.order.size()) {
            long wall = System.currentTimeMillis() - startedAt;
            LOGGER.info("[dlb] {} TERMINE : {} chunks, cpu={} ms, ecoule={} ms, ratio={}",
                    name, zone.chunkCount(), cpuNanos / 1_000_000L, wall,
                    String.format("%.1f", wall / Math.max(1.0, cpuNanos / 1e6)));
            if (onDone != null) onDone.run();
        } else {
            level.getServer().execute(this::tick);
        }
    }
}
```

⚠ **Le `LOGGER.info` de fin imprime CPU ET temps écoulé.** C'est une obligation
du §79 : annoncer « la passe coûte 838 ms » alors qu'elle bloque la chaîne
pendant 3,5 s est un mensonge qui a déjà coûté une journée d'analyse.

## §111. Bloc 6 — la passe principale `dressAndPlant`

C'est le cœur. Elle remplace **à la fois** `verifyGrassSurface` et
`naturalize`, en un seul balayage.

**Ce qu'elle fait, colonne par colonne :**

1. trouver la surface ;
2. choisir le bloc de sol (palette + mélange) et le poser ;
3. réécrire 3 blocs de sous-sol si nécessaire ;
4. remettre la neige si le chunk est enneigé ;
5. décider s'il faut planter, et quoi ;
6. poser la plante après vérification de `canSurvive`.

🔒 **Un seul parcours.** Les deux anciennes passes faisaient deux balayages
complets sur les mêmes 40 000 colonnes. C'est l'invariant I5 : **ne jamais
ajouter une passe, toujours fusionner**.

```java
/**
 * Point d'entree : lance l'habillage complet.
 *
 * @param extraRing marge au-dela de terrainRing(), pour que la bande de
 *                  melange ait de la matiere des deux cotes
 */
public static void startDressAndPlant(ServerLevel level, int cx, int cz,
                                      int extraRing, Runnable onDone) {
    paletteFallbacks = 0; rescueTotal = 0;
    dressedColumns = 0; plantedColumns = 0; blendedColumns = 0;

    int ring = terrainRing() + extraRing;
    ChunkMajorZone zone = new ChunkMajorZone(cx, cz, ring);

    LOGGER.info("[dlb] dressAndPlant DEBUT : rayon={}, {} chunks",
            ring, zone.chunkCount());

    // Phase 1 : echantillonnage de TOUTES les palettes.
    // Obligatoire avant la phase 2 : pickGround lit les 8 voisins, donc
    // il faut que le voisinage entier soit connu avant de poser le
    // moindre bloc. Sinon le premier chunk traite n'a aucun voisin et
    // ne melange pas, tandis que le dernier melange avec des chunks
    // DEJA REECRITS : le degrade se propagerait en cascade.
    new ChunkPass(level, zone, "palette",
        (lv, chunk, z) -> PALETTE.put(chunk.getPos().toLong(), samplePalette(lv, chunk)),
        () -> {
            LOGGER.info("[dlb] palette : {} chunks echantillonnes, {} sans echantillon",
                    PALETTE.size(), paletteFallbacks);

            // Phase 2 : habillage proprement dit.
            new ChunkPass(level, zone, "dressAndPlant",
                StructureTerrainPrep::dressAndPlant,
                () -> {
                    LOGGER.info("[dlb] dressAndPlant : {} colonnes habillees, "
                              + "{} melangees ({} %), {} plantees, {} sauvetages",
                            dressedColumns, blendedColumns,
                            dressedColumns == 0 ? 0 : 100 * blendedColumns / dressedColumns,
                            plantedColumns, rescueTotal);
                    PALETTE.clear(); SNOWY_CELL.clear(); RESCUE.clear();
                    if (onDone != null) onDone.run();
                }).tick();
        }).tick();
}

/**
 * Habille un chunk : sol, sous-sol, neige, vegetation. Un seul parcours.
 */
private static void dressAndPlant(ServerLevel level, LevelChunk chunk, ChunkMajorZone zone) {
    long key = chunk.getPos().toLong();
    SurfacePalette local = PALETTE.get(key);
    if (local == null) return;

    int cx = chunk.getPos().x, cz = chunk.getPos().z;

    // Les 8 voisins, lus UNE FOIS pour les 256 colonnes.
    SurfacePalette[] nb = new SurfacePalette[8];
    nb[NB_NW] = paletteAt(cx - 1, cz - 1);
    nb[NB_N]  = paletteAt(cx,     cz - 1);
    nb[NB_NE] = paletteAt(cx + 1, cz - 1);
    nb[NB_W]  = paletteAt(cx - 1, cz);
    nb[NB_E]  = paletteAt(cx + 1, cz);
    nb[NB_SW] = paletteAt(cx - 1, cz + 1);
    nb[NB_S]  = paletteAt(cx,     cz + 1);
    nb[NB_SE] = paletteAt(cx + 1, cz + 1);

    boolean snowy = isSnowyCell(level, chunk);
    int baseX = chunk.getPos().getMinBlockX();
    int baseZ = chunk.getPos().getMinBlockZ();

    // UNE seule position mutable pour tout le chunk. Ne pas allouer
    // dans la boucle : 256 allocations par chunk x 2500 chunks = 640 000.
    BlockPos.MutableBlockPos mut = new BlockPos.MutableBlockPos();

    for (int dx = 0; dx < 16; dx++) {
        for (int dz = 0; dz < 16; dz++) {
            int x = baseX + dx, z = baseZ + dz;

            if (!zone.contains(x, z))   continue;   // hors anneau
            if (isInsideFootprint(x, z)) continue;  // sous la structure

            int y = surfaceY(chunk, dx, dz);
            if (y <= level.getMinBuildHeight()) continue;

            mut.set(x, y, z);
            BlockState cur = chunk.getBlockState(mut);
            Block curB = cur.getBlock();

            // On ne touche NI l'eau NI la construction. La reparation des
            // plans d'eau appartient a fixWaterNearStructure ; y toucher
            // ici reproduirait l'inondation.
            if (curB == Blocks.WATER || curB == Blocks.ICE) continue;
            if (!isGroundCandidate(curB) && !curB.defaultBlockState().isAir()) continue;

            // --- 1. le bloc de surface ---------------------------------
            Block want = pickGround(x, z, local, nb);
            if (curB != want) {
                level.setBlock(mut, want.defaultBlockState(), FAST_FLAG);
            }
            dressedColumns++;

            // --- 2. le sous-sol ----------------------------------------
            Block filler = fillerFor(want);
            for (int d = 1; d <= SUBSOIL_DEPTH; d++) {
                mut.set(x, y - d, z);
                Block sub = chunk.getBlockState(mut).getBlock();
                if (sub == Blocks.AIR || sub == Blocks.WATER) break;   // falaise, grotte
                if (sub == Blocks.STONE || sub == Blocks.DEEPSLATE)   break;   // roche : on s'arrete
                if (sub != filler) {
                    level.setBlock(mut, filler.defaultBlockState(), FAST_FLAG);
                }
            }

            // --- 3. la neige -------------------------------------------
            if (snowy) applySnowLayer(level, mut, x, y, z, want);

            // --- 4. la vegetation --------------------------------------
            mut.set(x, y, z);
            plantOn(level, chunk, mut, x, y, z, want, key);
        }
    }

    // --- 5. les plantes sauvees, une fois le sol du chunk refait -------
    replantRescued(level, chunk, zone);
}
```

**Explication de l'ordre interne.** Le sol doit être posé **avant** la
végétation, sinon `canSurvive` interroge l'ancien sol. La neige doit venir
**après** le sol et **avant** la végétation, sinon la plante occupe la case où
la neige irait. Le sauvetage vient **en dernier**, quand tout le chunk est
stable — c'est aussi ce qui permet de compter les emplacements libres restants.

## §112. Bloc 7 — surface, emprise, neige

```java
/**
 * Hauteur du premier bloc solide, en sautant la couverture.
 *
 * On part de WORLD_SURFACE_WG et on descend. WG = worldgen : cette
 * heightmap ignore les blocs poses par les joueurs et les structures,
 * ce qui est exactement ce qu'on veut ici.
 */
private static int surfaceY(LevelChunk chunk, int dx, int dz) {
    int y = chunk.getHeight(Heightmap.Types.WORLD_SURFACE_WG, dx, dz);
    BlockPos.MutableBlockPos m = new BlockPos.MutableBlockPos();
    int wx = chunk.getPos().getMinBlockX() + dx;
    int wz = chunk.getPos().getMinBlockZ() + dz;
    for (int step = 0; step < 8; step++) {
        m.set(wx, y, wz);
        Block b = chunk.getBlockState(m).getBlock();
        if (!isSkippableCover(b) && !b.defaultBlockState().isAir()) return y;
        y--;
    }
    return y;
}

/**
 * Le chunk est-il enneige ?
 *
 * Mis en cache : la requete de biome coute cher (resolution de la
 * source de biomes, interpolation), et la reponse est identique pour
 * les 256 colonnes du chunk. C'est le commit 2 du plan.
 */
private static boolean isSnowyCell(ServerLevel level, LevelChunk chunk) {
    long key = chunk.getPos().toLong();
    Boolean cached = SNOWY_CELL.get(key);
    if (cached != null) return cached;

    BlockPos center = new BlockPos(
            chunk.getPos().getMiddleBlockX(), 80, chunk.getPos().getMiddleBlockZ());
    Holder<Biome> biome = level.getBiome(center);
    boolean snowy = biome.value().coldEnoughToSnow(center);
    SNOWY_CELL.put(key, snowy);
    return snowy;
}

/**
 * Remet une couche de neige si le sol l'accepte.
 *
 * On pose SNOW avec une seule couche : vanilla en empilerait davantage
 * avec le temps, mais une couche suffit a l'oeil et coute un seul setBlock.
 */
private static void applySnowLayer(ServerLevel level, BlockPos.MutableBlockPos mut,
                                   int x, int y, int z, Block ground) {
    if (ground == Blocks.SAND || ground == Blocks.RED_SAND) return;
    mut.set(x, y + 1, z);
    if (!level.getBlockState(mut).isAir()) return;
    BlockState snow = Blocks.SNOW.defaultBlockState()
            .setValue(SnowLayerBlock.LAYERS, 1);
    if (snow.canSurvive(level, mut)) {
        level.setBlock(mut, snow, FAST_FLAG);
    }
}
```

**Recommandation sur `coldEnoughToSnow`.** Cette méthode est `public` en 1.21.1
mais son nom a changé plusieurs fois entre versions. Si le build échoue,
l'alternative stable est de comparer `biome.value().getBaseTemperature() < 0.15f`.
**Ne cherche pas midi à quatorze heures : c'est un détail de 2 lignes.**

## §113. Bloc 8 — la végétation

**La découverte qui change tout.** On croyait devoir écrire une table
« quel végétal sur quel sol ». **C'est inutile et c'est faux.** Minecraft
possède déjà la réponse :

```java
BlockState.canSurvive(LevelReader level, BlockPos pos)
```

Chaque bloc porte sa propre règle. `SugarCaneBlock.canSurvive` teste déjà les
tags `DIRT`/`SAND`/`RED_SAND` **et** la présence d'eau latérale.
`CactusBlock.canSurvive` teste déjà le sable **et** l'absence de voisin solide.

**Conséquences :**

- une table écrite à la main serait **redondante** avec le code vanilla ;
- elle serait **fausse** dès qu'un mod ajoute une plante ;
- elle **dériverait** à chaque mise à jour de Minecraft.

🔒 **Décision D14 : on n'écrit aucune table de compatibilité. On propose un
candidat et on demande à `canSurvive` s'il tient.**

Le seul rôle du code local est de **proposer un candidat plausible** — on ne va
pas tester les 1 200 blocs du registre pour chaque colonne.

```java
/**
 * Table de proposition (PAS de validation).
 *
 * Elle repond a "qu'est-ce qui pousse plausiblement ici", pas a
 * "est-ce que ca tient" : la seconde question est posee a canSurvive.
 *
 * Les poids sont des entiers cumules : on tire un entier dans [0, total[
 * et on prend le premier depasse. Plus rapide qu'une liste de flottants.
 */
private static Block proposePlant(Block ground, float r) {
    if (ground == Blocks.GRASS_BLOCK) {
        if (r < 0.62f) return Blocks.SHORT_GRASS;
        if (r < 0.74f) return Blocks.TALL_GRASS;
        if (r < 0.80f) return Blocks.FERN;
        if (r < 0.84f) return Blocks.POPPY;
        if (r < 0.88f) return Blocks.DANDELION;
        if (r < 0.91f) return Blocks.CORNFLOWER;
        if (r < 0.94f) return Blocks.AZURE_BLUET;
        if (r < 0.96f) return Blocks.OXEYE_DAISY;
        if (r < 0.98f) return Blocks.BROWN_MUSHROOM;
        return Blocks.RED_MUSHROOM;
    }
    if (ground == Blocks.PODZOL || ground == Blocks.MYCELIUM) {
        if (r < 0.45f) return Blocks.FERN;
        if (r < 0.70f) return Blocks.LARGE_FERN;
        if (r < 0.85f) return Blocks.BROWN_MUSHROOM;
        return Blocks.RED_MUSHROOM;
    }
    if (ground == Blocks.SAND) {
        if (r < 0.70f) return Blocks.DEAD_BUSH;
        return Blocks.CACTUS;
    }
    if (ground == Blocks.RED_SAND) {
        if (r < 0.80f) return Blocks.DEAD_BUSH;
        return Blocks.CACTUS;
    }
    if (ground == Blocks.SNOW_BLOCK) {
        return Blocks.AIR;   // rien ne pousse sur la neige : on s'abstient
    }
    if (ground == Blocks.MUD || ground == Blocks.CLAY) {
        if (r < 0.60f) return Blocks.SHORT_GRASS;
        return Blocks.SUGAR_CANE;
    }
    if (ground == Blocks.MOSS_BLOCK) {
        if (r < 0.50f) return Blocks.MOSS_CARPET;
        if (r < 0.80f) return Blocks.SHORT_GRASS;
        return Blocks.AZALEA;
    }
    if (ground == Blocks.GRAVEL || ground == Blocks.STONE) {
        return Blocks.AIR;
    }
    if (ground.getDescriptionId().contains("terracotta")) {
        return r < 0.85f ? Blocks.AIR : Blocks.DEAD_BUSH;
    }
    return Blocks.AIR;
}

/** Densite de vegetation par type de sol, en fraction de colonnes. */
private static float plantDensity(Block ground) {
    if (ground == Blocks.GRASS_BLOCK) return 0.34f;
    if (ground == Blocks.PODZOL)      return 0.28f;
    if (ground == Blocks.MYCELIUM)    return 0.22f;
    if (ground == Blocks.MOSS_BLOCK)  return 0.40f;
    if (ground == Blocks.MUD)         return 0.18f;
    if (ground == Blocks.CLAY)        return 0.10f;
    if (ground == Blocks.SAND)        return 0.035f;
    if (ground == Blocks.RED_SAND)    return 0.045f;
    return 0.0f;
}

/**
 * Tente de planter sur une colonne. Ne pose rien si ca ne tient pas.
 */
private static void plantOn(ServerLevel level, LevelChunk chunk,
                            BlockPos.MutableBlockPos mut,
                            int x, int y, int z, Block ground, long chunkKey) {

    float density = plantDensity(ground);
    if (density <= 0f) return;
    if (posNoise(x, z, SALT_PLANT) >= density) return;

    Block plant = proposePlant(ground, posNoise(x, z, SALT_PICK));
    if (plant == Blocks.AIR) return;

    mut.set(x, y + 1, z);
    if (!level.getBlockState(mut).isAir()) return;

    if (plant == Blocks.CACTUS)      { placeStack(level, mut, x, y, z, plant, 3); return; }
    if (plant == Blocks.SUGAR_CANE)  { placeStack(level, mut, x, y, z, plant, 3); return; }
    if (plant == Blocks.TALL_GRASS
     || plant == Blocks.LARGE_FERN)  { placeDouble(level, mut, x, y, z, plant); return; }

    BlockState st = plant.defaultBlockState();
    if (st.canSurvive(level, mut)) {
        level.setBlock(mut, st, FAST_FLAG);
        plantedColumns++;
    }
}

/**
 * Pose une pile (cactus, canne a sucre) de hauteur 1 a max.
 *
 * On verifie canSurvive a CHAQUE etage : le cactus casse si un voisin
 * horizontal est solide, et cette condition peut etre vraie au niveau 1
 * et fausse au niveau 2.
 */
private static void placeStack(ServerLevel level, BlockPos.MutableBlockPos mut,
                               int x, int y, int z, Block plant, int max) {
    int h = 1 + (int) (posNoise(x, z, SALT_STACK) * max);
    BlockState st = plant.defaultBlockState();
    int placed = 0;
    for (int i = 1; i <= h; i++) {
        mut.set(x, y + i, z);
        if (!level.getBlockState(mut).isAir()) break;
        if (!st.canSurvive(level, mut)) break;
        level.setBlock(mut, st, FAST_FLAG);
        placed++;
    }
    if (placed > 0) plantedColumns++;
}

/**
 * Pose une plante a deux blocs de haut.
 *
 * ATTENTION : avec les mises a jour de voisinage, poser la moitie BASSE
 * en premier la fait casser immediatement (elle ne trouve pas sa moitie
 * haute). Deux solutions : poser la HAUTE d'abord, ou poser les deux sans
 * mise a jour de voisinage. FAST_FLAG contient le drapeau 16
 * (pas de mise a jour), donc l'ordre BAS puis HAUT est sur ici — mais on
 * verifie quand meme canSurvive sur la moitie basse avant.
 */
private static void placeDouble(ServerLevel level, BlockPos.MutableBlockPos mut,
                                int x, int y, int z, Block plant) {
    BlockState lower = plant.defaultBlockState()
            .setValue(DoublePlantBlock.HALF, DoubleBlockHalf.LOWER);
    BlockState upper = plant.defaultBlockState()
            .setValue(DoublePlantBlock.HALF, DoubleBlockHalf.UPPER);

    mut.set(x, y + 1, z);
    if (!lower.canSurvive(level, mut)) return;
    BlockPos lowerPos = mut.immutable();

    mut.set(x, y + 2, z);
    if (!level.getBlockState(mut).isAir()) return;

    level.setBlock(lowerPos, lower, FAST_FLAG);
    level.setBlock(mut,      upper, FAST_FLAG);
    plantedColumns++;
}
```

⚠ **Piège 1.21.1 documenté.** Certaines plantes testent la luminosité dans
`canSurvive`. Pendant la génération, `getRawBrightness` renvoie **0** parce que
la lumière n'est pas encore calculée : la plante échoue silencieusement. Si des
plantes disparaissent sans explication, **c'est la première piste** — pas ton
code. Contournement : poser sans passer par `canSurvive` pour cette famille
précise, ou différer la plantation après le calcul de lumière.

⚠ **Piège du cactus.** Le cactus casse si **l'un des 4 voisins horizontaux est
solide**. Or notre passe habille les colonnes dans l'ordre : si on pose un
cactus puis qu'on habille la colonne voisine avec un bloc solide au même Y, le
cactus tombe. **D'où la règle : traiter les cactus en dernier**, une fois tout
le sol du chunk posé. Dans la version ci-dessus ils sont posés en ligne ; si le
test montre des cactus manquants, sors-les dans une seconde boucle du même
parcours de chunk (pas une passe supplémentaire).

## §114. Bloc 9 — le sauvetage des plantes

**Le problème.** `clearSurfaceDecor` retire tout le décor de surface. Après le
terrassement, on repose de la végétation générique. **Les plantes rares du
biome d'origine sont perdues** : lys, orchidées de marais, plantes de mods.

**La solution retenue (décision D13).** On ne sauvegarde **pas les positions** —
elles n'ont plus de sens après remodelage, le sol a bougé de plusieurs blocs.
On sauvegarde un **inventaire par chunk** : « ce chunk contenait 3 lys et
7 orchidées ». Puis on replante ce nombre à des positions valides quelconques
du même chunk.

**Pourquoi c'est mieux :** l'inventaire est minuscule (une `Map<Block,Integer>`
de quelques entrées par chunk), il survit à n'importe quel remodelage, et il
préserve ce qui compte visuellement — **la composition florale**, pas les
coordonnées exactes.

```java
/**
 * Blocs que naturalize() savait deja poser. Calcule une seule fois.
 *
 * Inutile de "sauver" une paquerette : la passe normale en reposera.
 * On ne sauve que ce que la passe normale ne sait PAS reproduire.
 */
private static Set<Block> knownByNaturalize() {
    if (knownByNaturalizeCache != null) return knownByNaturalizeCache;
    Set<Block> s = new HashSet<>();
    s.add(Blocks.SHORT_GRASS);   s.add(Blocks.TALL_GRASS);
    s.add(Blocks.FERN);          s.add(Blocks.LARGE_FERN);
    s.add(Blocks.POPPY);         s.add(Blocks.DANDELION);
    s.add(Blocks.CORNFLOWER);    s.add(Blocks.AZURE_BLUET);
    s.add(Blocks.OXEYE_DAISY);   s.add(Blocks.BROWN_MUSHROOM);
    s.add(Blocks.RED_MUSHROOM);  s.add(Blocks.DEAD_BUSH);
    s.add(Blocks.CACTUS);        s.add(Blocks.SUGAR_CANE);
    s.add(Blocks.MOSS_CARPET);   s.add(Blocks.AZALEA);
    s.add(Blocks.SNOW);
    knownByNaturalizeCache = s;
    return s;
}

/**
 * Cette plante merite-t-elle d'etre sauvee ?
 *
 * Critere : c'est une plante de SOL (pas une liane, pas une feuille),
 * et naturalize ne sait pas la reproduire.
 *
 * BushBlock est le filet a mods : la quasi-totalite des plantes modees
 * en heritent, donc on les attrape sans connaitre leur nom.
 */
private static boolean isRescuable(BlockState st) {
    Block b = st.getBlock();
    if (knownByNaturalize().contains(b)) return false;
    return isGroundPlant(st);
}

/** Plante posee sur le sol, par opposition a une liane ou une feuille. */
private static boolean isGroundPlant(BlockState st) {
    Block b = st.getBlock();
    if (b instanceof BushBlock)        return true;
    if (b instanceof DoublePlantBlock) return true;
    if (b instanceof SugarCaneBlock)   return true;
    if (b instanceof CactusBlock)      return true;
    return false;
}

/**
 * Note une plante retiree dans l'inventaire de son chunk.
 * A appeler depuis scanTrees, la ou le decor est deja parcouru :
 * ZERO balayage supplementaire (invariant I5).
 */
private static void noteRescue(BlockState st, int x, int z) {
    if (rescueTotal >= RESCUE_MAX_TOTAL) return;
    if (!isRescuable(st)) return;
    long key = ChunkPos.asLong(x >> 4, z >> 4);
    Map<Block, Integer> inv = RESCUE.computeIfAbsent(key, k -> new HashMap<>());
    int n = inv.values().stream().mapToInt(Integer::intValue).sum();
    if (n >= RESCUE_MAX_PER_CHUNK) return;
    inv.merge(st.getBlock(), 1, Integer::sum);
    rescueTotal++;
}

/**
 * Melange deterministe d'un indice dans [0,256[.
 *
 * Pourquoi ? Si on replante en parcourant les colonnes dans l'ordre,
 * toutes les plantes sauvees atterrissent dans le coin nord-ouest du
 * chunk. Il faut un ordre pseudo-aleatoire mais reproductible.
 *
 * k est impair, donc n -> n*k mod 256 est une BIJECTION : on visite
 * les 256 colonnes exactement une fois chacune, sans doublon ni oubli.
 * Verifie sur 6400 chunks cette session.
 */
private static int scramble(int n, int cx, int cz) {
    int k = (int) (posNoise(cx, cz, 0x2C1B) * 251) | 1;
    return (n * k + (cx * 7 + cz * 13)) & 255;
}

/** Replante l'inventaire d'un chunk. */
private static void replantRescued(ServerLevel level, LevelChunk chunk, ChunkMajorZone zone) {
    long key = chunk.getPos().toLong();
    Map<Block, Integer> inv = RESCUE.remove(key);
    if (inv == null || inv.isEmpty()) return;

    int cx = chunk.getPos().x, cz = chunk.getPos().z;
    int baseX = chunk.getPos().getMinBlockX();
    int baseZ = chunk.getPos().getMinBlockZ();
    BlockPos.MutableBlockPos mut = new BlockPos.MutableBlockPos();

    int cursor = 0, tries = 0;
    for (Map.Entry<Block, Integer> e : inv.entrySet()) {
        BlockState st = e.getKey().defaultBlockState();
        int remaining = e.getValue();

        while (remaining > 0 && tries < RESCUE_MAX_TRIES) {
            tries++;
            int idx = scramble(cursor++, cx, cz);
            int dx = idx & 15, dz = (idx >> 4) & 15;
            int x = baseX + dx, z = baseZ + dz;
            if (!zone.contains(x, z))    continue;
            if (isInsideFootprint(x, z)) continue;
            if (tryPlaceRescued(level, chunk, mut, x, dx, dz, z, st)) remaining--;
        }
    }
}

/** Essaie de poser une plante sauvee sur une colonne. */
private static boolean tryPlaceRescued(ServerLevel level, LevelChunk chunk,
                                       BlockPos.MutableBlockPos mut,
                                       int x, int dx, int dz, int z, BlockState st) {
    int y = surfaceY(chunk, dx, dz);
    mut.set(x, y + 1, z);
    if (!level.getBlockState(mut).isAir()) return false;
    if (!st.canSurvive(level, mut))        return false;

    if (st.getBlock() instanceof DoublePlantBlock) {
        BlockPos lowerPos = mut.immutable();
        mut.set(x, y + 2, z);
        if (!level.getBlockState(mut).isAir()) return false;
        level.setBlock(lowerPos, st.setValue(DoublePlantBlock.HALF, DoubleBlockHalf.LOWER), FAST_FLAG);
        level.setBlock(mut,      st.setValue(DoublePlantBlock.HALF, DoubleBlockHalf.UPPER), FAST_FLAG);
        return true;
    }

    level.setBlock(mut, st, FAST_FLAG);
    return true;
}
```

## §116. Recommandation n°1 — réparer `fixWaterNearStructure`

### Le diagnostic

La consigne était : « les bords sont bons mais il reste des trous secs,
multiplie le rayon de fixwater par 4 ». Elle a été appliquée littéralement :

```java
int margin = Math.max(FIXLIQ_FORCE_MARGIN, terrainRing() + 16);   // 48 minimum
int rx = baseRx * FIXLIQ_REPAIR_SCALE;   // x4
int rz = baseRz * FIXLIQ_REPAIR_SCALE;   // x4
```

Bornes résultantes : environ **868 × 988 blocs**. Résultat : **la carte a été
inondée**. Cinq captures d'écran le confirment.

**Pourquoi ?** Parce que la réparation ne demandait pas *s'il devait y avoir de
l'eau ici*. Elle remplissait jusqu'au niveau de référence toute colonne située
sous ce niveau. À 48 blocs de rayon, ça touchait la cuvette du lac. À 4× ce
rayon, ça a touché les vallées voisines.

🔒 **Le rayon n'est pas le problème. L'absence de critère l'est.** Il faut
garder la portée large, et ajouter deux verrous.

### Verrou 1 — ne jamais remplir une colonne sèche

Une colonne mérite d'être réparée **seulement si elle portait de l'eau avant**,
ou si elle est **adjacente à de l'eau existante**. Une colonne sèche entourée de
sec reste sèche, quelle que soit son altitude.

```java
/**
 * Cette colonne a-t-elle le droit de recevoir de l'eau ?
 *
 * Trois conditions, dont une au moins doit etre vraie :
 *  - elle contenait de l'eau avant le terrassement (empreinte memorisee) ;
 *  - un de ses 4 voisins porte de l'eau au niveau cible ou au-dessus ;
 *  - elle est dans l'emprise du lac declare par la structure.
 *
 * Sinon : ON NE TOUCHE PAS. C'est la regle qui manquait.
 */
private static boolean mayReceiveWater(ServerLevel level, LevelChunk chunk,
                                       BlockPos.MutableBlockPos mut,
                                       int x, int z, int targetY) {
    if (WATER_FOOTPRINT.contains(ChunkPos.asLong(x, z))) return true;

    for (Direction d : Direction.Plane.HORIZONTAL) {
        int nx = x + d.getStepX(), nz = z + d.getStepZ();
        mut.set(nx, targetY, nz);
        if (level.getBlockState(mut).getFluidState().isSource()) return true;
    }
    return false;
}
```

### Verrou 2 — ne jamais dépasser le niveau du plan d'eau connecté

```java
/**
 * Niveau maximal autorise pour cette colonne.
 *
 * On ne remonte JAMAIS au-dessus de la surface libre du plan d'eau
 * auquel la colonne est reellement connectee. Sans ce plafond, une
 * reparation calee sur le niveau de la mer noie une mare de montagne.
 *
 * @return le Y de la surface, ou Integer.MIN_VALUE si aucun plan d'eau
 *         connecte n'a ete trouve dans le rayon de recherche
 */
private static int connectedWaterLevel(ServerLevel level, BlockPos.MutableBlockPos mut,
                                       int x, int z, int searchRadius) {
    int best = Integer.MIN_VALUE;
    for (int r = 1; r <= searchRadius; r++) {
        for (int i = -r; i <= r; i++) {
            int[][] probes = { { x + i, z - r }, { x + i, z + r },
                               { x - r, z + i }, { x + r, z + i } };
            for (int[] p : probes) {
                int y = level.getHeight(Heightmap.Types.WORLD_SURFACE, p[0], p[1]);
                for (int dy = 0; dy < 8; dy++) {
                    mut.set(p[0], y - dy, p[1]);
                    if (level.getBlockState(mut).getFluidState().isSource()) {
                        best = Math.max(best, y - dy);
                        break;
                    }
                }
            }
        }
        if (best != Integer.MIN_VALUE) return best;   // le plus proche gagne
    }
    return best;
}
```

### Le remplissage corrigé

```java
private static void repairColumn(ServerLevel level, LevelChunk chunk,
                                 BlockPos.MutableBlockPos mut,
                                 int x, int z, int referenceY) {

    // --- VERROU 1 -----------------------------------------------------
    if (!mayReceiveWater(level, chunk, mut, x, z, referenceY)) return;

    // --- VERROU 2 -----------------------------------------------------
    int connected = connectedWaterLevel(level, mut, x, z, 8);
    if (connected == Integer.MIN_VALUE) return;      // pas de plan d'eau : on s'abstient
    int targetY = Math.min(referenceY, connected);

    // --- remplissage, de bas en haut, sans depasser -------------------
    int groundY = level.getHeight(Heightmap.Types.OCEAN_FLOOR, x, z);
    for (int y = groundY + 1; y <= targetY; y++) {
        mut.set(x, y, z);
        BlockState st = level.getBlockState(mut);
        if (!st.isAir() && !st.getFluidState().isEmpty()) continue;
        if (!st.isAir()) break;                       // obstacle solide : on arrete
        level.setBlock(mut, Blocks.WATER.defaultBlockState(), FAST_FLAG);
    }
}
```

### L'empreinte d'eau, à mémoriser AVANT le terrassement

```java
/**
```

## §117. Recommandation n°2 — l'ancrage avec repli mesuré

### Le problème

L'ancrage échoue parfois et retombe sur une valeur brute non mesurée. La
structure s'enfonce alors de 2 à 4 blocs — c'est l'affaissement signalé.

### Le principe

Un repli **doit être mesuré**, jamais deviné. La médiane du sol est la bonne
statistique : contrairement à la moyenne, elle ignore les valeurs aberrantes
(un arbre, un pic rocheux, un trou).

```java
/**
 * Y d'ancrage d'une structure.
 *
 * Ordre de preference :
 *  1. la valeur mesuree par l'analyse de site (si elle existe et est fiable) ;
 *  2. la MEDIANE du sol sur une grille de sondage (repli mesure) ;
 *  3. rien : on refuse de coller. Mieux vaut pas de structure qu'une
 *     structure enterree.
 *
 * L'offset du modele est applique DANS TOUS LES CAS, y compris au repli.
 * C'est l'oubli de cette ligne qui produisait l'affaissement.
 */
private static int resolveAnchorY(ServerLevel level, int cx, int cz,
                                  int radius, SiteAnalysis site, String model) {
    int offset = modelOffset(model);

    if (site != null && site.isMeasured() && site.confidence() >= 0.8f) {
        return site.groundY() + offset;
    }

    LOGGER.warn("[dlb] ancrage : analyse de site indisponible ou peu fiable, "
              + "repli sur la mediane mesuree");

    int median = medianGroundY(level, cx, cz, radius);
    if (median == Integer.MIN_VALUE) {
        LOGGER.error("[dlb] ancrage IMPOSSIBLE : aucun sol mesurable. Collage annule.");
        return Integer.MIN_VALUE;
    }
    return median + offset;
}

/** Offsets verticaux par modele. Mesures, ne pas modifier sans remesurer. */
private static int modelOffset(String model) {
    return switch (model) {
        case "dragon"      -> -34;
        case "citadel"     -> -35;
        case "observatory" -> -5;
        case "crimsonlake" -> -10;   // enfoncement du lac
        default            -> 0;
    };
}

/**
 * Mediane du sol sur une grille de 32x32 sondages.
 *
 * On ignore : l'eau (le fond ne compte pas), les feuillages, les troncs.
 * On utilise OCEAN_FLOOR_WG, qui donne le sol solide sous l'eau et sous
 * la vegetation, sans tenir compte des constructions.
 */
private static int medianGroundY(ServerLevel level, int cx, int cz, int radius) {
    int step = Math.max(1, (2 * radius) / 32);
    List<Integer> ys = new ArrayList<>(1024);
    for (int x = cx - radius; x <= cx + radius; x += step) {
        for (int z = cz - radius; z <= cz + radius; z += step) {
            if ((x - cx) * (x - cx) + (z - cz) * (z - cz) > radius * radius) continue;
            if (!level.hasChunk(x >> 4, z >> 4)) continue;
            ys.add(level.getHeight(Heightmap.Types.OCEAN_FLOOR_WG, x, z));
        }
    }
    if (ys.isEmpty()) return Integer.MIN_VALUE;
    ys.sort(Integer::compare);
    int median = ys.get(ys.size() / 2);

    LOGGER.info("[dlb] mediane du sol : {} ({} sondages, min={}, max={})",
            median, ys.size(), ys.get(0), ys.get(ys.size() - 1));
    return median;
}
```

🔒 **Ne jamais utiliser `WORLD_SURFACE` pour un ancrage.** Elle renvoie le
sommet des arbres. Sur une forêt dense, l'écart avec le sol réel atteint
15 blocs — largement de quoi expliquer un affaissement apparent de 2 à 4 blocs
quand seulement une partie des sondages tombe dans les arbres.

## §119. Recommandation n°4 — durcir la sélection de site

Le défaut : en cas d'échec, la sélection retombe sur un candidat brut jamais
mesuré. On colle alors sur un terrain dont on ne sait rien.

```java
/**
 * Choisit un site. Refuse de renvoyer un candidat non mesure.
 *
 * Regle : un candidat ne devient eligible qu'apres avoir passe
 * l'analyse complete. Un candidat brut n'est PAS un repli acceptable ;
 * c'est la source des collages sur pente, des structures a moitie dans
 * la falaise, et des affaissements.
 */
private static SiteAnalysis selectSite(ServerLevel level, List<BlockPos> candidates,
                                       String model) {
    List<SiteAnalysis> measured = new ArrayList<>();

    for (BlockPos c : candidates) {
        SiteAnalysis a = analyseSite(level, c, model);
        if (a == null || !a.isMeasured()) continue;
        if (a.slope() > MAX_SLOPE)        continue;
        if (a.waterFraction() > MAX_WATER_FRACTION && !model.equals("crimsonlake")) continue;
        measured.add(a);
    }

    if (measured.isEmpty()) {
        // ❌ ANCIEN COMPORTEMENT : return new SiteAnalysis(candidates.get(0));
        // ✅ NOUVEAU : on echoue franchement et on elargit la recherche.
        LOGGER.warn("[dlb] {} : aucun candidat mesure valide sur {} testes. "
                  + "Elargissement de la recherche.", model, candidates.size());
        return null;
    }

    measured.sort(Comparator.comparingDouble(SiteAnalysis::score).reversed());
    SiteAnalysis best = measured.get(0);
    LOGGER.info("[dlb] {} : site retenu {} (score={}, pente={}, eau={} %)",
            model, best.pos(), String.format("%.2f", best.score()),
            String.format("%.2f", best.slope()),
            Math.round(best.waterFraction() * 100));
    return best;
}
```

🔒 **Échouer franchement vaut mieux que réussir mal.** Une recherche élargie
coûte quelques secondes ; une structure collée sur un site non mesuré coûte une
partie entière.

## §120. Recommandation n°5 — réduire `fixLiquids` (34,3 s, 32 %)

**Premier poste du dragon.** `/fixwater` et `/fixlava` sont appliqués sur toute
la boîte englobante. Or la boîte est un **rectangle**, la zone travaillée est un
**disque** : on traite déjà π/4 ≈ 79 % de surface utile, soit **21 % de pur
gaspillage**. Et sur ces 79 %, la grande majorité des colonnes n'a jamais vu
d'eau.

```java
/**
 * Decoupe la boite en sous-boites, et n'envoie /fixwater que sur celles
 * qui contiennent effectivement du liquide.
 *
 * Gain attendu : proportionnel a la fraction de sous-boites sechent.
 * Sur le dragon, 239 715 blocs d'eau repartis sur 46 539 colonnes parmi
 * 40 176 colonnes travaillees : l'eau est CONCENTREE, pas diffuse.
 * On s'attend a eliminer plus de la moitie des sous-boites.
 */
private static List<BoundingBox> wetSubBoxes(ServerLevel level, BoundingBox full, int cell) {
    List<BoundingBox> wet = new ArrayList<>();
    BlockPos.MutableBlockPos mut = new BlockPos.MutableBlockPos();

    for (int x0 = full.minX(); x0 <= full.maxX(); x0 += cell) {
        for (int z0 = full.minZ(); z0 <= full.maxZ(); z0 += cell) {
            int x1 = Math.min(x0 + cell - 1, full.maxX());
            int z1 = Math.min(z0 + cell - 1, full.maxZ());
            if (subBoxHasLiquid(level, mut, x0, z0, x1, z1, full.minY(), full.maxY())) {
                wet.add(new BoundingBox(x0, full.minY(), z0, x1, full.maxY(), z1));
            }
        }
    }
    LOGGER.info("[dlb] fixLiquids : {} sous-boites humides retenues", wet.size());
    return wet;
}

/**
 * Test rapide : la sous-boite contient-elle du liquide ?
 *
 * On echantillonne une grille de 4x4 plutot que de tout scanner.
 * Faux negatif possible sur une flaque de moins de 4 blocs : acceptable,
 * /fixwater ne servirait a rien dessus de toute facon.
 */
private static boolean subBoxHasLiquid(ServerLevel level, BlockPos.MutableBlockPos mut,
                                       int x0, int z0, int x1, int z1, int y0, int y1) {
    int sx = Math.max(1, (x1 - x0) / 4);
    int sz = Math.max(1, (z1 - z0) / 4);
    for (int x = x0; x <= x1; x += sx) {
        for (int z = z0; z <= z1; z += sz) {
            int h = level.getHeight(Heightmap.Types.WORLD_SURFACE, x, z);
            for (int dy = 0; dy < 6 && h - dy >= y0; dy++) {
                mut.set(x, h - dy, z);
                if (!level.getBlockState(mut).getFluidState().isEmpty()) return true;
            }
        }
    }
    return false;
}
```

**Recommandation de réglage :** commence avec `cell = 64`. Trop petit, le coût
du test de détection dépasse le gain ; trop grand, on ne filtre plus rien.
**Mesure les deux, garde le gagnant, supprime le perdant** — c'est exactement le
protocole du §80.

## §121. Recommandation n°6 — réduire `preload` (30,6 s, 29 %)

**Ce n'est pas du calcul, c'est de l'attente.** On ne l'accélérera pas en
optimisant du code. Trois leviers, par ordre de rendement attendu.

### Levier A — demander moins de chunks

La zone préchargée est carrée ; la zone travaillée est un disque. **21 % des
chunks chargés ne servent jamais.**

```java
/**
 * N'enumere que les chunks reellement touches.
 *
 * On ajoute une marge de 1 chunk : la bande de melange et fixWater
 * lisent chez le voisin immediat.
 */
private static List<ChunkPos> chunksToPreload(int cx, int cz, int ring) {
    List<ChunkPos> out = new ArrayList<>();
    int ccx = cx >> 4, ccz = cz >> 4;
    int cr = (ring >> 4) + 1;
    long r2 = (long) (cr + 1) * (cr + 1);
    for (int x = ccx - cr; x <= ccx + cr; x++) {
        for (int z = ccz - cr; z <= ccz + cr; z++) {
            long d2 = (long) (x - ccx) * (x - ccx) + (long) (z - ccz) * (z - ccz);
            if (d2 <= r2) out.add(new ChunkPos(x, z));
        }
    }
    return out;
}
```

### Levier B — demander plus tôt

Le préchargement est lancé juste avant l'usage. On attend donc la latence
complète. Si on lance la demande **dès la sélection du site**, la génération se
fait pendant l'analyse et le collage : le temps d'attente devient du temps
masqué.

```java
// Dans selectSite, juste apres avoir retenu le meilleur candidat :
startPreload(level, best.pos().getX(), best.pos().getZ(), terrainRing(), null);
// ... l'analyse detaillee et la preparation continuent pendant ce temps ...
```

⚠ **Attention à ne pas précharger pour un candidat qui sera rejeté.** Ne lance
qu'après la décision finale, sinon on génère des chunks inutiles et on aggrave
le problème.

### Levier C — épingler les chunks

Un chunk chargé puis relâché puis rechargé coûte deux fois. Vérifie avec le log
que ça n'arrive pas :

```java
LOGGER.info("[dlb] preload : {} demandes, {} deja presents, {} generes, {} ms",
        requested, alreadyLoaded, generated, elapsed);
```

🔒 **Si `generated` est très inférieur à `requested`, le préchargement n'est pas
le goulot : c'est l'attente du ticket de chunk.** Le diagnostic change
complètement, et les leviers A et B deviennent inutiles. **Mesure avant
d'optimiser.**

## §123. Recommandation n°8 — la règle d'or du chantier

> **Ne jamais optimiser un poste avant de l'avoir mesuré, et ne jamais mesurer
> autre chose que le temps écoulé de bout en bout.**

Le dragon fait **107,5 s**. La cible est **30 s**. Il faut donc gagner **77,5 s**.
Voici ce que rapportent les leviers, dans l'ordre :

|---|---|---|---|

## §124. `ab_tramage.py` — le protocole A/B

**Ce qu'il fait.** Il compare deux stratégies de tramage sur une frontière
longue, et mesure deux choses :

1. **la fidélité** : l'écart entre la proportion obtenue et la proportion
   visée, à chaque distance du bord ;
2. **la structure** : le nombre de motifs distincts observés sur une fenêtre
   glissante.

**Pourquoi deux critères ?** Parce que la fidélité seule ne détecte pas un
damier. Un damier parfait a une fidélité impeccable **et** une structure
visible à l'œil. C'est le second critère qui a condamné le tramage ordonné.

```python
# Coeur du protocole. BORDER = 1024, pas 16.
def fidelity_and_structure(strategy, border=1024, band=5):
    errors, patterns = [], set()
    for d in range(1, band + 1):
        target = (band + 1 - d) * 0.5 / band
        hits = sum(1 for i in range(border) if strategy(i, d) )
        errors.append(abs(hits / border - target) * 100)
        row = tuple(strategy(i, d) for i in range(32))
        patterns.add(row)
    return sum(errors) / len(errors), len(patterns)
```

⚠ **Ne descends jamais sous 512 échantillons.** Avec 16 cellules, l'écart-type
binomial vaut ±11,5 points — **plus grand que l'effet mesuré**. C'est exactement
l'erreur qui a produit une conclusion fausse au §53, retirée depuis.

**Résultats obtenus, à ne pas refaire :**

| Stratégie | Erreur de fidélité | Motifs distincts sur 32 |
|---|---|---|
| **hash de position** | **0,68 pt** | **25 / 32** |
| bayer 4×4 | 6,00 pt | 4 / 32 |
| bayer 8×8 | 6,00 pt | 4 / 32 |
| hybride, gigue 0,1 | 9,57 pt | 7 |
| hybride, gigue 0,3 | 6,12 pt | 12 |
| hybride, gigue 0,5 | 4,40 pt | 17 |
| hybride, gigue 0,7 | 3,21 pt | 21 |
| hybride, gigue 0,9 | 2,61 pt | 24 |

🔒 **Le tramage ordonné est définitivement rejeté**, et ce n'est pas un problème
de réglage. La probabilité varie le long de l'axe **perpendiculaire** à la
frontière, qui est aussi un axe de la matrice de Bayer : les seuils se
quantifient en 50/50/25/25/**0 %** au lieu de 50/40/30/20/10 %. **La rangée la
plus extérieure est toujours vide.** Ne rouvre pas ce débat.

🔒 **Les hybrides sont monotones** : plus de gigue, plus on se rapproche du hash
pur. Il n'existe aucun réglage intermédiaire meilleur que le hash. Abandonné.

## §125. `test_periodicite_hash.py` — le hash est-il périodique ?

Écrit parce qu'on soupçonnait `posNoise` de produire des bandes. **Il a été
innocenté.**

```python
# Sur 6400 chunks : moyenne 0.4985, ecart-type 0.2889.
# Theorie pour une loi uniforme sur [0,1[ : 0.5 et 0.2887.
# Autocorrelation a tous les pas de 1 a 64 : |r| < 0.02.
# Verdict : aucune periodicite. Le probleme visuel venait de
```

**Leçon de méthode.** Le symptôme était « on voit des lignes ». Le coupable
supposé était le générateur aléatoire. Le vrai coupable était la **forme de la
zone** où on l'appliquait. **Avant d'accuser un composant, mesure-le isolément.**

## Les trois choses à retenir

1. **L'habillage, c'est 2 % du temps.** Fais-le bien, mais ne crois pas que ça
   réglera le problème des 30 secondes. Le vrai chantier est au Livre XV.
2. **Mesure avant de changer, mesure après, et journalise même les échecs.**
   Le tableau des cinq gigues rejetées vaut plus que la conclusion seule.
3. **Ne baisse jamais un seuil pour faire passer un test.** Si le dragon ne
   passe pas sous 30 s, dis-le, chiffre l'écart, et propose un septième levier.
